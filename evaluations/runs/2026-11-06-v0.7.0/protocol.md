# v0.7.0 실행 절차

## 목적과 자료

실제 프로젝트에서 스킬을 사용한 뒤 받은 피드백은 긴 문단, 발견별 소제목 부족, 반복되는 면책과 판단 꼬리표, 문장 중간의 긴 근거 경로를 지적했다. 이번 실행은 이 네 문제를 스킬과 예시에서 고친다.

공개 회귀 사례 두 개는 같은 문제 유형을 새 이름·수치·경로로 구성한 가상 자료다. 실재 프로젝트의 파일이나 측정 결과를 옮기지 않았다. 원자료와 필수 의미·독자 질문은 [고정 기록](source-freeze.json)에, 생성에 쓴 스킬은 [별도 고정 기록](skill-freeze.json)에 남겼다. 피드백을 보고 지침과 사례를 설계했으므로 미리 보지 않은 주제의 일반화 실험으로 분류하지 않는다.

## 기존 12개 문서

v0.6.0에서 공개한 최종본 12개를 그대로 보존했다. 기존 본문·원자료·평가 조건이 바뀌지 않았으므로 필수 의미 177개와 독자 질문 47개의 판정을 출처와 함께 재사용했다. 재사용은 새 독립 검토 건수에 포함하지 않는다.

문단 구조는 [산문 통계](audit/retained-structure.json)로 다시 확인했다. 일반 산문 토큰의 최대 길이는 220자였으며 250자를 넘는 토큰은 없었다. 이 결과는 이번에 지적된 과밀 문단 유형을 찾는 보조 자료다. 기존 의미 검토 기록과 바이트 일치를 함께 근거로 보존했다.

## 두 버전의 교정

두 작성자는 각각 새 대화 맥락에서 고정된 스킬 하나와 같은 초안 두 개만 읽었다. 사용자 피드백, 필수 의미 계약, 질문·예상 답, 다른 조건의 출력과 검토 기록은 전달하지 않았다. 두 초안 모두 사실·조건·수치·식별자·근거를 유지해 개발 인계 문서로 다듬으라는 같은 요청을 포함한다.

| 조건 | 제공한 스킬 | 최초 제출 위치 |
| --- | --- | --- |
| previous | v0.6.0 고정본 | `forward/previous/` |
| current | v0.7.0 고정본 | `forward/current/` |

이번에 작성한 previous는 v0.6.0 지침을 사용한 비교용 출력이다. 과거 릴리스에서 이미 발표했던 문서로 취급하지 않는다. 조건별로 두 사례를 한 번씩 작성했으며, 최초 제출은 이후 교정과 별개로 보존한다.

생성과 검토에는 세션에서 제공한 GPT-6 Astra Pro 계열 에이전트를 사용했다. 배포 모델 식별자와 샘플링 매개변수는 노출되지 않았다. 사용자가 실제 프로젝트에서 함께 사용한 다른 문체·도식 스킬은 이 실행에 포함하지 않았다.

## 의미·탐색·문체 검토

새 두 사례의 계약에는 필수 의미 24개와 독자 질문 10개가 있다. 버전을 가린 A/B 본문을 별도 검토자에게 제공하고, 원자료·계약과 대조한 판정, 정확한 인용, 독자 질문의 답을 찾은 위치를 기록한다. 비교 결과는 단회 출력에서 관측한 차이로 해석한다.

설계 검토의 K11은 원자료에 있는 지속 실패 시 간격 증가 조건이 제공 초안에는 명시되지 않은 입력 차이가 발견됐다. 첫 출력의 부분 충족 판정은 그대로 보존하되, 이 조건을 스킬이 삭제한 정보나 버전별 성능 차이로 세지 않는다. 최종 교정에서는 원자료를 대조해 조건을 보완했다. [입력 차이 기록](audit/generation-input-gap.json)에 근거와 해석을 남겼다.

문체 검토에서는 문단 길이 하나로 우열을 정하지 않는다. 서로 다른 질문이 분리됐는지, 같은 질문에 답하는 결과와 근거는 연결됐는지, 제목의 확실성이 본문과 일치하는지, 긴 근거를 옮긴 뒤에도 경로·행 범위·주장 대응을 추적할 수 있는지 확인한다.

최초 출력에서 발견한 실제 누락이나 모호함은 별도 수정 이력을 남겨 고친다. 최종 문서는 `outputs/revised/`에 두고 원자료와 다시 대조한다. [공개 예시](../../../docs/examples/README.md)는 최종본과 같은 바이트로 생성한다. 원문에 필요한 미검증 범위와 중단 조건은 편집 문제로 오인해 삭제하지 않는다.

## 배포 검사

[통합 계약](release-contract.json)은 기존 10개 사례, v0.6.0 신규 2개 사례, 이번 2개 사례의 계약을 변경 없이 합친 것이다. 필수 의미 201개와 독자 질문 57개를 포함한다. 원래 선택 항목을 필수로 승격하거나 이전 기준을 낮추지 않는다.

최종 배포 검사는 14개 사례의 출력·검토·공개 예시 대응, 필수 의미와 질문의 완료 판정, 여섯 편집 기준의 해결 근거, 고정한 스킬 여섯 파일을 확인한다. 코드는 판정행·해시·정확한 인용의 무결성을 검사하며 의미 판정은 검토 기록에 따른다.

HTML과 Markdown 비교는 같은 manifest에서 다시 만든다. 과거 미적용 원문 8개, 이전·현재 본문 각 14개, 입력 14개를 포함하는 HTML의 선택·목차·다운로드와 브라우저 배치는 기존 검사기로 확인한다.

## 해석 범위

이번 결과는 두 가상 보고서의 교정과 기존 문서의 보존 확인이다. 사람의 읽는 시간·피로·기억과 반복 생성의 안정성은 측정하지 않았다. 실제 프로젝트 자료에서 제공된 발췌의 교정은 별도 보고서로 전달하고 공개 회귀 자료와 구분했다.
