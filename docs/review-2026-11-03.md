# 추가 리뷰 검토와 후속 평가 초안

검토일: 2026-11-03 · 반영본: v0.2.1 · 아래 내용은 당시의 검토와 후속 평가 제안입니다. v0.3.0 당시 결과는 [보존한 보고서](evaluation-v0.3.0.md), v0.4.0의 결과는 [현재 비교 보고서](evaluation.md)에 있습니다. 아래에서 제안한 반복 생성 실험은 실행하지 않았습니다.

사용자가 전달한 Gemini 협업 리뷰를 [검토 당시 저장소](https://github.com/hostkimjang/korean-dev-writing-skills/tree/dc0c3f8db1c712c1ccc4ed68577f89f69809d666)와 대조했다. 문서별 소제목 흐름은 선택형 예시로 보강했다. 아래의 평가 계획은 다음 실행을 준비하기 위한 초안이며 기존 결과에 소급 적용하지 않는다.

## 지적별 판단과 반영

| 리뷰 내용 | 현재 자료와 대조한 판단 | 처리 |
| --- | --- | --- |
| 사실·의미 보존을 단문화보다 우선했다 | 판단 순서, 불확실성·조건·지원 범위 보존 지침과 일치한다. | 기존 원칙 유지 |
| 표현 교정·구조 정리·새 문서 작성을 구분했다 | 작업 범위와 추가 질문 조건이 명시되어 있다. 실제 질문 횟수의 감소는 측정하지 않았다. | 지침의 의도와 관찰 결과를 구분 |
| 과잉 교정의 부작용을 차단·해소했다 | 위험한 규칙과 예시를 고쳤다는 근거는 있다. 기존 실험에서는 세 조건 모두 사실 정확성 점수가 같아 오류 발생률 감소를 입증하지는 못했다. | 효과를 보장하는 표현은 채택하지 않음 |
| 불필요한 분량을 31~48% 줄였다 | 세 긴 문서의 전체 글자 수 감소율은 맞다. 빠진 모든 설명이 불필요했다고 평가한 것은 아니다. | 길이와 품질을 별도로 보고 |
| 반복·번역투 감점 지표를 추가하면 변별력이 높아진다 | 기존 기준에도 두 항목이 있다. 새 지표가 변별력을 높이는지는 별도 검증이 필요하다. | 다음 실행용 관찰 기준을 아래에 제안 |
| 비-README 문서의 소제목 흐름을 보강하자 | 짧은 예시는 도움이 될 수 있다. 버그·장애 기록에는 이미 조사 흐름 안내가 있었다. | 필요한 항목만 고르는 예시로 보강 |
| `나누실 때는`, `작업 디렉토리`를 고치자 | 현재 `SKILL.md`는 이미 `나눌 때는`, `작업 디렉터리`다. | 재현되지 않아 수정하지 않음 |
| 정적 검사로 Markdown 구조 깨짐을 방지한다 | 검사기가 지원하는 문법과 구조 오류를 탐지한다. 모든 Markdown·HTML·링크를 검증하지는 않는다. | [검사 범위](development.md)를 기준으로 설명 |

## v0.2.1에서 바꾼 내용

`references/document-types.md`에 PR, 아키텍처, ADR, 운영 절차, API, 튜토리얼, 기술 글의 소제목 흐름 예시를 보강했다. 버그·장애 기록의 기존 조사 흐름은 중복해서 추가하지 않는다. 예시는 자료와 독자의 목적에 따라 합치거나 순서를 바꾸고, 필요한 항목만 선택한다.

ADR의 제안·승인 상태를 구분하고, 운영 절차의 중단 조건을 해당 단계에서 확인하는 원칙은 유지한다. 소제목을 채우려고 대안·원인·복구 명령을 새로 만드는 지침이 아니다.

설치되는 참고 파일이 달라졌으므로 패키지 기본 버전을 v0.2.1로 올렸다. 기존 비교의 평가 대상은 [v0.2.0 고정본](https://github.com/hostkimjang/korean-dev-writing-skills/tree/dc0c3f8db1c712c1ccc4ed68577f89f69809d666/skills/korean-dev-writing)이며, 이 고정본의 파일 해시는 [실행 기록](../evaluations/runs/2026-11-03/manifest.json)에 있다. 기존 입력·평가 기준·출력·평가자 기록·점수는 보존한다. **구성 예시 보강의 글쓰기 효과는 아직 측정하지 않았다.**

## 다음 평가에서 확인할 질문

현재 기준은 다섯 차원의 0~4점 평가다. 반복은 구조와 자연스러움에서, 번역투는 자연스러움에서 이미 판단한다. 새 지표의 목적은 특정 조건의 점수 차이를 크게 만드는 것이 아니라, 어떤 문장이 읽기를 방해했고 무엇이 그대로 필요했는지 설명하는 데 있다.

1. 같은 설명을 여러 절에 둔 것이 실제 탐색이나 이해를 방해하는가?
2. 필요한 경고·조건·확인 절차를 유지하면서 반복을 줄였는가?
3. 명사화·대동사·번역투를 고칠 때 시제·상태·주체·확실성이 바뀌지 않는가?
4. 문장을 나누거나 합쳤을 때 조건과 동작, 지시 대상이 더 명확해지는가?
5. 소제목 흐름 예시가 짧은 문서의 불필요한 절을 늘리거나, 없는 정보를 채우게 만들지는 않는가?

## 다음 실행용 보조 관찰 기준

기존 총점과 별도로 기록할 후보 항목이다. 단어 출현 횟수나 글자 수를 자동 점수로 바꾸지 않는다. 한 문제를 여러 차원에 반영하려면 각 차원에 미친 다른 영향을 설명한다.

| 관찰 항목 | 문제가 있다고 판단할 근거 | 함께 확인할 예외 |
| --- | --- | --- |
| 절 사이의 반복 | 같은 명제의 두 위치를 인용하고, 새 설명 없이 되풀이되어 판단이나 탐색을 늦추는 이유를 제시한다. | 요약과 상세 설명, 독립적으로 읽는 절의 전제, 실행 직전의 경고·확인 조건은 목적 있는 반복일 수 있다. |
| 명사화·대동사·번역투 | 문제 구절에서 행위·주체·조건이 왜 모호하거나 장황한지 설명하고, 같은 뜻을 더 분명하게 쓸 수 있는지 판단한다. | `진행하다`, `이루어지다`의 사용 자체는 결함이 아니다. 진행 중 상태나 자연스러운 피동을 지우거나 미확인 주체를 만들지 않는다. |
| 기계적 단문화 | 문장을 나눈 탓에 적용 조건이나 지시 대상이 끊겨 독자가 관계를 다시 구성해야 하는 구절을 찾는다. | 서로 독립된 실행 단계나 병렬 항목을 짧게 분리한 것은 결함이 아니다. |
| 핵심 정보의 배치 | 독자의 실제 질문과 필요한 정보의 위치를 대조한다. 실행 뒤에야 필수 선행조건을 알 수 있다면 그 영향을 기록한다. | 모든 문서에 결론·금지 조치를 첫 문장으로 강제하지 않는다. 각 절의 독자와 읽는 순서를 본다. |
| 의미 보존 | 원자료의 조건·예외·가능성·제안 상태·검증 수준이 유지되는지 대조한다. | 더 짧거나 자연스럽다는 이유로 누락이나 확신의 강화를 상쇄하지 않는다. |

각 관찰에는 고유 ID, 출력 구절과 위치, 원자료의 관련 항목, 독자에게 생기는 부담, 예외 해당 여부, 관련 평가 차원을 남긴다. 중복 문제는 두 위치를 함께 적고, 같은 문제를 여러 번 집계하지 않는다. 영향은 `문제 없음 / 국소 수정 필요 / 여러 부분 수정 필요 / 작업·판단 방해`처럼 서술하되 새 총점으로 자동 합산하지 않는다.

평가자가 문제를 찾지 못한 항목도 기록한다. 자연스러운 피동이나 목적 있는 반복을 유지한 사례를 함께 확인해, 많이 고치거나 많이 줄인 문서에 무조건 유리한 평가가 되지 않게 한다.

## 후속 실험 설계 초안

실행 전에 사례, 조건, 생성 반복 수, 모델과 설정, 평가 방식과 기록 양식을 동결한다. 이 문서만으로 평가가 실행되었거나 기준의 신뢰도가 검증되었다고 보지 않는다.

- **입력:** 기존 출력에 맞춰 새 기준을 조정하지 않고 신규 사례를 마련한다. 정상적인 피동·가능성·필요한 반복을 보존해야 하는 사례와, 실제 중복·번역투·끊긴 단문을 고칠 사례를 함께 포함한다. 제안 상태의 ADR, 원인이 미확정인 장애 기록, 짧은 PR처럼 목차 확대가 불필요한 경우도 넣는다.
- **조건:** 스킬 미적용, 평가에 사용한 v0.2.0, 구성 예시를 보강한 v0.2.1을 같은 입력과 같은 생성 설정으로 비교한다. 각 조건의 파일 해시를 기록한다. 조건마다 새 컨텍스트를 사용한다.
- **반복:** 예비 설계로 신규 사례 6개 × 조건 3개 × 독립 생성 3회, 총 54개 출력을 제안한다. 수와 실행 범위는 생성 전에 확정하며 결과를 본 뒤 유리한 출력만 고르지 않는다. 54개 출력을 서로 다른 54개 업무 사례처럼 해석하지 않는다.
- **평가:** 조건을 가린 절대 평가 뒤 짝 비교를 추가한다. 짝 비교는 입력·독자·목적을 기준으로 선호 또는 동점과 이유를 기록하고, 표시 순서는 균형 있게 배정한다. 가능하면 다른 모델 계열이나 실제 개발자 평가를 포함하며, 확보하지 못했다면 그 한계를 기록한다.
- **독해 확인:** 가능할 때 실제 독자가 핵심 조건을 찾아 답하는 정확도, 필요한 수정 구절과 검토 부담을 확인한다. 모델이 추정한 읽기 시간을 실제 사용자 측정값으로 보고하지 않는다.
- **보고:** 차원별 점수 분포, 최상위 점수의 비율, 평가자 간 불일치, 짝 비교의 선호·동점, 원문 근거를 함께 제시한다. 짧아진 문서에서 정보가 빠지거나 안내가 덜 유용해진 사례도 포함한다. 반복 생성이 사례 다양성이나 독립적인 사람 평가를 대신하지 않는다.

기존의 [프로토콜](../evaluations/protocol.md), [평가 기준](../evaluations/rubric.json), [2026-11-03 실행 기록](../evaluations/runs/2026-11-03/manifest.json)은 이 초안과 분리한다. 새 기준이 필요하면 다음 실행의 별도 버전으로 확정하고, 과거 결과의 점수는 소급 변경하지 않는다.
