# 개발 문서 빠른 교정 규칙

이 문서는 한국어 개발 안내·명세·검증 기록을 처리할 때 항상 읽습니다. 일반 한국어 규칙은 [기존 통합 룰북](ai-tell-rulebook.md)을 함께 적용하며, 아래 개발 규칙은 해당 문맥에서 우선합니다. 정본 매핑은 [development-rules.json](development-rules.json)입니다.

정규식은 후보를 찾는 도구로만 사용합니다. 코드·명령·실제 식별자와 사실의 강도를 먼저 보호하고, 문맥을 확인한 뒤 문장마다 고칩니다. 표의 교정 전 열은 탐지용 예문이며 제품 문서에 남길 표현이 아닙니다.

## A. 번역투

### DEV-A01. 개발 직역 조어

기술 용어를 한자어로 옮긴 표현은 기능과 대상을 드러내도록 풉니다. 사전의 권장 표현은 조건부 선택지이며, 저장 방식·수량·정상 여부를 새로 단정하는 근거로 사용하지 않습니다.

사전의 권장 표현은 어휘 표제어로 제시합니다. 실제 문장에서는 문서의 시제와 경어체에 맞게 활용합니다.

### DEV-A02. 분열문

목적·이유를 별도 명사절로 감싸지 말고 주체와 동작을 직접 연결합니다. 목적 표현을 필요조건으로 바꾸거나 원인과 결과를 뒤집지 않습니다.

| 교정 전 | 교정 후 | 보존 기준 |
| --- | --- | --- |
| 재시도한 이유는 요청을 완료하기 위해서입니다. | 요청을 완료하도록 재시도했습니다. | 목적과 과거 시제를 유지합니다. |
| 토큰을 확인하는 것은 권한을 검증하기 때문입니다. | 권한을 검증하므로 토큰을 확인합니다. | 이유를 그대로 연결합니다. |
| 요청을 보내는 데 필요한 것은 토큰을 등록하는 것입니다. | 요청을 보내려면 토큰을 등록해야 합니다. | 원문에 필요조건이 명시된 경우에만 적용합니다. |

### DEV-A03. 기능동사

검증·실행·저장·처리 같은 동작은 구체적인 동사로 씁니다. 행위자가 없으면 새로 추가하지 않으며, 진행 중인 상태를 완료로 바꾸지 않습니다.

| 교정 전 | 교정 후 |
| --- | --- |
| 입력 검증을 수행합니다. | 입력을 검증합니다. |
| 스크립트 실행을 진행합니다. | 스크립트를 실행합니다. |
| 설정 저장이 이루어집니다. | 설정이 저장됩니다. |
| 상태 변경을 수행합니다. | 상태를 바꿉니다. |

### DEV-A04. 조사와 매개구

장소·수단·기준을 구분하고, 동작을 더 분명하게 설명하는 조사나 동사를 고릅니다. 실제 매개 관계가 중요하면 그 의미를 생략하지 않습니다.

| 교정 전 | 교정 후 |
| --- | --- |
| 서버에서의 검증 결과를 확인합니다. | 서버에서 검증한 결과를 확인합니다. |
| API를 통해 상태를 조회합니다. | API로 상태를 조회합니다. |
| 설정을 기반으로 대상을 선택합니다. | 설정을 기준으로 대상을 선택합니다. |

## C. 명세와 기록

### DEV-C01. 현행 명세와 실행 이력

현행 명세에는 현재의 구조·API 계약·운영 절차를 남깁니다. 한 번 실행해 생긴 작업 경로, 프로세스 번호, 컨테이너 값과 단계별 수정·검사 기록은 별도의 이력 문서로 옮기고 링크를 연결합니다. 관례적으로 `work_history.md`나 `docs/evidence/`를 사용할 수 있으나, 먼저 저장소에 실제로 존재하는 기록 경로를 확인합니다.

고정된 서비스 포트·운영 경로·재현 명령·현재의 미해결 제한은 유지합니다. 실행 기록을 옮길 때 값과 코드 블록을 그대로 보존하며, 원본 보존용 사본은 편집하지 않습니다.

### DEV-C02. 객관적인 검증 범위

제품 설명에서는 작업 도구의 대화 구분을 제거합니다. 정리된 검증 기록에서는 검토 범위·실행 단계·실행 제약으로 설명합니다. 실행이 거부되었거나 아직 확인하지 못한 상태를 성공으로 바꾸지 않습니다.

| 교정 전 | 교정 후 |
| --- | --- |
| 이 채팅에서 확인했습니다. / 이번 채팅에서 확인했습니다. | 이 검토 범위에서 확인했습니다. |
| API 채팅에서 확인했습니다. | API 검증 단계에서 확인했습니다. |
| root 채팅에서 확인했습니다. / 주관 채팅에서 확인했습니다. | 통합 검토 범위에서 확인했습니다. |
| 이 worker가 서버를 검증했습니다. | 서버 검증 단계에서 확인했습니다. |
| `turn_context`, `model=...`, `effort=...` | 제품 문서에서 제거하고 재현에 필요한 설정만 별도 기록에 보존합니다. |
| 자동 승인 검토에서 blocked by policy로 거부되었습니다. | 실행 정책 제한으로 거부되었습니다. |

실제 제품의 필드명·API 매개변수·프로세스 이름과 같은 식별자는 문구가 비슷해도 번역하지 않습니다. 보호된 원시 실행 결과는 수정하지 않고, 독자가 읽는 설명만 정리합니다.

## E. 종결어미

### DEV-E01. 문서 세트 통일

개발 안내·명세의 본문은 경어체로 통일합니다. 현재 계약은 현재형으로, 확인을 마친 기록은 과거형으로 씁니다. 특정 파일만 고르지 말고 대상 목록의 모든 본문과 완결된 문장형 표 셀을 끝까지 확인합니다. 이 규칙은 리듬을 위해 어미를 바꾸라는 일반 문체 권고보다 우선합니다.

짧은 명사구 표 셀은 문장으로 늘리지 않습니다. 코드 블록의 주석·명령·출력, 변경 금지 인용문과 원본 보존용 사본은 원형을 유지합니다. 규칙 설명의 교정 전 예문은 실제 문서 본문과 구분해 검사합니다.

| 교정 전 | 교정 후 |
| --- | --- |
| 요청을 처리한다. | 요청을 처리합니다. |
| 설정이 바뀐다. | 설정이 바뀝니다. |
| 검증을 마쳤다. | 검증을 마쳤습니다. |
| 이 값은 기준값이다. | 이 값은 기준값입니다. |
