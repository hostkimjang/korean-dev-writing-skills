# 달무리 설정배포 안내

설정 묶음은 워크스페이스 전체에 적용되며 활성 묶음은 최대 하나입니다. 일부 사용자만 따로 적용할 수 없습니다.

## 1. 준비

조회자는 상태·이력을 보고, 편집자는 초안 작성·저장·유효성 검사를 합니다. 적용 요청과 예약 취소에는 배포자 역할이 필요합니다. 역할을 겸할 수 있지만 편집자만으로는 요청할 수 없습니다.

초안에 작업 요청의 기본 상한과 알림 휴지 시간대를 모두 입력하고 검사하세요. 통과 후 수정했다면 다시 검사해야 합니다.

## 2. 적용 요청

검사를 통과한 초안을 선택하세요. 같은 워크스페이스에 `SCHEDULED` 배포가 있으면 활성화되거나 취소될 때까지 새 요청을 접수하지 않습니다. 모든 시각은 UTC입니다.

- **일반 적용:** `activate_at`을 서버 접수 시각보다 5분 이상 뒤로 지정합니다(정확히 5분 포함).
- **초기 전용 적용:** 활성 이력이 없는 `UNCONFIGURED` 워크스페이스의 첫 요청에만 `apply_now: true`를 쓸 수 있습니다. `activate_at`은 보내지 않으며 5분 대기는 면제됩니다. 검사 통과·배포자 역할·기존 예약 없음 조건은 그대로입니다.

두 방식 모두 접수 성공 시 HTTP 202, 새 `release_id`, `state: SCHEDULED`를 받습니다. 접수는 적용 완료가 아닙니다.

## 3. 실제 적용 확인

`release_id`를 기록하고 콘솔 배포 이력에서 같은 요청의 상세를 열어 `state`, `activate_at`, `activated_at`을 확인하세요. 초기 전용 요청의 `activate_at`과 전환 전의 `activated_at`은 비어 있습니다.

서버는 명목상 30초마다 전환을 평가합니다. 일반 요청은 예정 시각 도달 후, 초기 전용 요청은 접수 후 첫 평가에서 `ACTIVE`로 전환합니다. 30초는 완료 시간 보장이 아닙니다. 전환 전에는 기존 묶음을 쓰며, 새 워크스페이스는 `UNCONFIGURED`를 유지합니다. 조회는 저장된 상태를 읽을 뿐 평가나 활성화를 유발하지 않습니다.

## 4. 변경과 평가 재개

접수된 내용은 수정할 수 없습니다. `SCHEDULED`일 때 배포자가 콘솔에서 예약 취소하면 `CANCELLED`가 되며 새 초안을 제출할 수 있습니다. `ACTIVE`는 예약 취소할 수 없으므로 이전 내용으로 되돌리려면 이전 묶음을 복사해 새 일반 적용을 요청하세요.

평가 재개 시 저장된 `SCHEDULED` 요청과 원래 `activate_at`을 이어 씁니다. 예정 시각이 지났다면 첫 평가의 전환 대상입니다. 새 ID 발급이나 5분 대기 재계산 없이 같은 `release_id`의 상세에서 확인하세요.

## 접수 거절 응답

| 조건 | HTTP | 본문 |
| --- | --- | --- |
| 검사 미통과·결과 무효 | 422 | `{"error":"BUNDLE_INVALID"}` |
| 기존 `SCHEDULED` 배포 있음 | 409 | `{"error":"PENDING_RELEASE_EXISTS"}` |
| 일반 요청의 서버 접수~예정 시각 간격이 5분 미만 | 400 | `{"error":"ACTIVATION_TOO_SOON"}` |
| 배포자 역할 없음 | 403 | `{"error":"RELEASE_ROLE_REQUIRED"}` |
| 활성 이력이 있는데 초기 전용 요청 | 409 | `{"error":"INITIAL_MODE_NOT_ALLOWED"}` |

422로 거절된 요청에는 `release_id`가 발급되지 않습니다. 거절 조건이 겹칠 때 반환 순서는 알 수 없습니다.
