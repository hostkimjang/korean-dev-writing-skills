# v0.6.0 수정과 확인 절차

이 실행은 기존 문서를 검토해 필요한 부분을 고치고, 비교 자료의 읽기·재생성 기능을 보완한다. 이전 문서, 최초 제출본, 검토 기록은 덮어쓰지 않는다.

## 기존 문서의 교정

대상은 v0.5.0의 기존 문서 10개다. 원자료와 기존 `preservation-v1` 계약을 그대로 사용한다. 별도 독자 관점 검토에서 발견한 문제를 완료 기준으로 고정한 뒤 해당 문서만 수정한다. 바꾸지 않은 문서는 기존 검토의 출처와 바이트 동일 여부를 기록한다.

교정자는 기존 문서와 수정 요청을 볼 수 있다. 따라서 이 결과는 지침만 제공한 단회 생성 실험이 아니라 피드백을 반영한 교정 결과다. 바뀐 문서는 다른 검토자가 원자료·필수 의미·탐색 질문·수정 기준과 대조한다. 해결 가능한 누락이나 배치 문제를 발견하면 다음 교정본에서 수정하고 다시 확인한다.

현재 배포본은 `outputs/revised/`에 둔다. `docs/examples/`의 해당 파일은 이 최종본과 같은 바이트여야 한다. 사례별 변경·보존 여부와 검토 출처는 최종 `manifest.json`에 기록한다.

## 새로운 주제의 작성

기존 사례 밖에서 지침을 확인하려고 로그 보관 정책과 구성 값 우선순위라는 가상 자료를 작성했다. 두 자료는 이 실행의 진행자가 만든 합성 사례다. 자료·입력·필수 의미·독자 질문은 후보 스킬 수정과 문서 생성 전에 고정했으며, 경로와 해시는 `source-freeze.json`에 남긴다.

두 주제에는 v0.5.0과 v0.6.0 지침을 각각 적용한다. 작성자에게는 실제 문서 작성 요청, 원자료, 지정한 스킬만 제공한다. 이전 출력과 검토의 정답·수정 기준은 제공하지 않는다. 최초 제출은 그대로 보존하고, 이후 수정이 필요하면 별도 파일로 구분한다.

검토자는 버전 이름을 가린 문서, 원자료, 사전 고정한 계약으로 필수 의미 27개와 독자 질문 10개를 대조한다. 버전당 한 번씩 작성하므로 문장 선택과 구성의 차이를 관찰할 수 있지만, 차이를 스킬 변경만의 효과로 분리해 추정할 수는 없다.

## 생성·검토 조건

작성·검토에는 세션에서 상속한 모델을 사용한다. 모델의 배포 식별자와 표본 추출 매개변수는 노출되지 않았다. 작성자와 검토자는 별도 컨텍스트를 사용하며, 누가 어떤 자료를 받았는지는 실행 기록에 남긴다.

분량 목표는 입력에 적힌 조건을 따른다. 문자 수는 공백·개행·Markdown 문법을 포함한 유니코드 코드 포인트 수로 센다. 글이 짧다는 사실을 더 잘 이해된다는 점수로 바꾸지 않는다.

## 파일·화면 검증

Markdown과 HTML은 저장소에 포함한 빌더로 생성한다. 검토 인용은 해당 문서의 정확한 부분 문자열이어야 하며, 원자료·문서·스킬 스냅샷의 해시를 대조한다. 배포 검사에서는 미해결 필수 의미·탐색 질문·구체적 수정 항목이 남은 최종본을 통과시키지 않는다.

화면 검사는 문서 선택, 절 이동, 원문 내려받기, 모바일 너비, 한 문서 읽기의 실제 동작을 대상으로 한다. 코드·DOM 검사와 실제 브라우저 검사를 구분해 보고한다. 검사 명령과 실행 결과는 개발 안내 및 검증 기록에 남긴다.

## 결과의 범위

사람을 모집해 읽는 시간·이해도·기억·피로를 측정한 실험은 아니다. 검토 결과는 제공된 자료에 대한 의미 보존과 구성의 판단이며, 화면 검증은 탐색과 표시 기능에 대한 확인이다. 구체적으로 수정한 문제와 관찰한 차이를 보고하고, 일반적인 향상률이나 완벽한 글쓰기 보장을 제시하지 않는다.
