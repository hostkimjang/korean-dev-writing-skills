# v0.5.0 문서 교정과 확인 절차

이 작업은 v0.4.0에서 확인한 편집 문제를 해결하고 바로 사용할 수 있는 문서를 완성한다. 원자료·기존 출력·수정 요청을 함께 보고 교정하므로 독립적인 블라인드 생성 실험으로 설명하지 않는다.

## 고정한 자료

- 기존 10개 원자료와 입력, v0.4.0 출력, 미적용 출력, 의미 보존 계약을 바꾸지 않는다. 파일 해시는 manifest.json에 기록한다.
- 설치용 v0.5.0 후보의 6개 파일을 snapshots/v0.5.0에 고정한다.
- 기존 결함과 추가 개선 목표 11개는 repair-checks.json에서 구분한다. 선택 정보였던 짧은 PR 로그 필드를 과거 필수 누락으로 다시 판정하지 않는다.

## 교정과 재검토

1. 편집자는 원자료, v0.4.0 문서, 스킬, 해당 완료 기준을 읽는다. 이미 충분한 문서는 보존할 수 있다.
2. 첫 교정본을 outputs/round-1에 보존한다. 이후 수정이 필요하면 별도 round 디렉터리에 기록한다.
3. 다른 검토자가 원자료에 대한 필수 의미 150개와 탐색 질문 37개를 기존 계약으로 확인한다. 완료 기준 11개도 실제 본문 증거로 확인한다.
4. 고칠 수 있는 누락·왜곡·분산·중복이 발견되면 문서를 수정하고 영향을 받은 조건을 재검토한다. 수정 가능한 문제를 단순한 한계로 남기지 않는다.
5. 완료 판정을 받은 문서만 outputs/revised와 docs/examples에 같은 바이트로 배포한다. 최종 인용·해시·문서 복사본 일치를 검사한다.

## 결과의 범위

평가는 모델의 원자료 대조와 정적 검사다. 사람의 읽기 속도·피로·이해도를 측정한 실험은 아니다. 자수 감소 자체를 개선 점수로 쓰지 않는다. 문서별 해결된 문제와 확인 근거를 공개한다.

## 별도 새 작성 확인

런북·짧은 PR·설정배포 안내는 새 컨텍스트 작성자가 스킬과 원래 입력만 읽고 작성했다. 기존 출력·수정 기준·검토 결과는 전달하지 않았다. 제출 뒤 본문을 고치지 않고 보존했으며, 다른 컨텍스트의 검토자가 원자료와 대조했다. 필수 의미 52개, 탐색 질문 15개와 이 세 사례에 해당하는 보완 기준 5개를 확인했고 수정할 열린 문제는 발견하지 못했다. `forward/`에 입력 전달 방식·첫 작성본·검토·해시를 남겼다.

## 최종 채택

편집자는 제출 전에 스스로 검토·조정했다. 이후 별도 검토에서 10개 교정 제출본의 필수 의미 150개와 탐색 질문 37개, 편집 완료 기준 11개를 확인했다. 추가 수정이 필요한 항목이 없어 `outputs/round-1/`을 그대로 `outputs/revised/`에 채택했다. 미실시 절차를 실행한 것처럼 기록하거나 과거 원문을 덮어쓰지 않았다.
