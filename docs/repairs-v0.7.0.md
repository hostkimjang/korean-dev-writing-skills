# v0.7.0: 조사·설계 보고서의 문단과 근거 배치 개선

실제 사용 피드백에서 지적한 **과밀 문단, 발견별 제목 부족, 반복 면책, 긴 근거 경로**를 스킬에 반영했다. 기존의 의미 보존·실행 조건·짧은 문서 규칙은 유지하고, 긴 조사와 검토 문서의 구성 지침을 구체화했다.

## 1. 네 문제를 어떻게 고쳤나

| 피드백 | 반영한 행동 | 적용 위치 |
| --- | --- | --- |
| 여러 실험·시점·권고가 긴 문단 하나에 섞임 | 문단이 3~4문장이나 250~300자를 넘으면 한 질문에 답하는지 다시 살핀다. 서로 다른 질문은 나누되 같은 질문에 답하는 비교·근거는 함께 설명한다. | [스킬 3절](../skills/korean-dev-writing/SKILL.md), [읽기 흐름 3절](../skills/korean-dev-writing/references/reading-flow.md) |
| 독립된 발견을 찾기 어려움 | 3개 이상 이어지는 조사·검토 결과에는 결론형 번호 소제목을 사용한다. 짧은 병렬 항목은 번호 목록으로 처리하고 기존 제목 위계를 따른다. | [문서 유형별 조사 보고서 구성](../skills/korean-dev-writing/references/document-types.md) |
| 면책과 `(판단)`이 반복됨 | 상태를 `확인했다`, `…로 보인다`, `권장한다`처럼 서술어로 드러낸다. 같은 범위의 반복 해명은 합치고 결론을 바꾸는 미대조·미검증 사실은 가까이 둔다. | [스킬 2절](../skills/korean-dev-writing/SKILL.md), [교정 예시](../skills/korean-dev-writing/references/before-after-guide.md) |
| 긴 경로·행 범위가 문장을 끊음 | 주장 바로 아래 근거 줄·목록·표로 옮긴다. 정확한 경로와 불연속 행 범위, 각 주장과의 대응을 유지한다. 실행 명령의 경로는 명령에 남긴다. | [스킬 5절](../skills/korean-dev-writing/SKILL.md), [읽기 흐름 7절](../skills/korean-dev-writing/references/reading-flow.md) |

문체 교정이나 도식 스킬을 함께 쓰더라도 필요한 제목·표·근거·실행 조건의 배치를 유지하도록 추가했다. 함께 쓰는 스킬의 문장 연결 작업 때문에 독립된 발견을 다시 한 문단으로 합치지 않게 하는 지침이다.

## 2. 정확성을 유지한 적용 방식

글자 수는 편집 위치를 찾는 신호로 삼았다. [Google의 문단 지침](https://developers.google.com/style/paragraph-structure)도 한 생각을 다루는 구조를 우선하고 문장 수에 맞추려고 문장을 길게 합치는 일을 피한다. 이번 한국어 자수 기준은 이 저장소의 편집 기준이며 실험으로 확인한 인지 한계가 아니다.

반복 면책은 서술을 고쳐 줄인다. 예를 들어 `첫 실증 후보로 권장한다`는 제안 상태를 이미 드러낸다. 반면 `운영 값은 대조하지 않았다`는 동일 계정·비밀값이라는 결론의 근거 범위를 바꾸므로 해당 설명 옆에 남긴다. [Google의 주의 사항 지침](https://developers.google.com/style/notices)을 참고해 실행 성공에 필요한 조건과 중단 기준도 해당 단계에 둔다.

긴 근거는 위치를 옮기고 내용은 유지한다. `71-79, 144-151`을 `71-151`로 바꾸면 확인 범위가 넓어진다. 같은 파일을 인용하더라도 주장별 대응을 보존하며, HTML에는 굵은 첫 문장만 쓰는 대신 실제 제목 요소를 사용하도록 했다. 관련 근거는 [연구·작성 지침 기록](reading-research.md)에 정리했다.

## 3. 공개 사례와 검토 범위

기존 최종본 12개는 그대로 보존했다. 이번에 일반 산문 토큰을 다시 세었을 때 최대 길이는 220자였고 250자를 넘는 토큰은 없었다. 본문·원자료·계약이 같아 필수 의미 177개와 독자 질문 47개의 기존 판정을 재사용했다.

새 가상 사례는 서로 다른 실험이 뒤섞인 조사 보고서와, 긴 경로·미대조 범위·교체 실행 조건이 섞인 설계 검토다. 원자료와 필수 의미 24개·독자 질문 10개를 고정한 뒤 같은 초안을 v0.6.0과 v0.7.0으로 각각 교정했다. 작성자는 다른 조건의 출력이나 평가 계약을 보지 않았다.

첫 교정본의 버전을 가린 검토와 최종 교정 결과를 아래에 기록했다. 실제 프로젝트의 정보는 공개 사례로 복사하지 않았다.

### 최초 교정본의 익명 검토

| 사례 | v0.6.0 첫 제출 | v0.7.0 첫 제출 | 읽기 구성 판정 |
| --- | --- | --- | --- |
| 조사 보고서 | 필수 의미 12/12 · 독자 질문 5/5 | 필수 의미 12/12 · 독자 질문 5/5 | 동률. v0.7.0은 결과별 재탐색과 조건 표, v0.6.0은 관련 실험을 이어 읽는 흐름에 강점이 있었다. |
| 설계 검토 | 필수 의미 11/12 · 독자 질문 4/5 | 필수 의미 11/12 · 독자 질문 4/5 | v0.7.0을 근소하게 선호. 발견 제목·역할 표·근거 범위의 분리가 재탐색에 유리했다. |

설계 검토의 부분 충족은 **지속 실패 시 재시도 간격을 늘린다는 조건**이다. 이 구절은 원자료에는 있지만 작성자에게 준 편집 초안에는 명시되지 않았다. 따라서 이 공통 차이를 스킬이 삭제한 정보나 두 버전의 성능 차이로 세지 않는다. [최초 판정](../evaluations/runs/2026-11-06-v0.7.0/forward/reviews/blind.md)과 [입력 대조 기록](../evaluations/runs/2026-11-06-v0.7.0/audit/generation-input-gap.json)을 함께 보존하고, 최종본에는 원자료에서 조건을 보완했다.

### 최종본에서 마친 교정

조사 보고서는 첫 제출에 남은 동일 평가 범위의 반복을 합쳤다. CPU/GPU 조건과 반복 횟수는 표에 모으고, 기계 정답·사람 미검수 조건은 평가 방법 옆에 한 번 뒀다. 권장 개발 순서에는 판정 경로 연결 뒤 독립 평가와 운영 일정 미정을 함께 남겼다.

설계 검토는 토큰 설명을 역할 표에 모으고 긴 제목을 줄였다. 실제 값 미대조·파일 열람 미실시·백업 내용 미열람은 각 판단 옆에 유지했다. 재시도 간격의 증가 조건을 보완하고 장기 장애의 복구 보장 미정을 해당 재시도 절에 붙였다. 키 교체의 중단 조건과 이전 키 폐기 기준은 제목과 같은 실행 절에서 찾을 수 있다.

두 최종본을 원자료·고정 계약과 다시 대조한 별도 검토에서는 필수 의미 **24/24개**, 독자 질문 **10/10개**, 편집 완료 기준 **6/6개**를 충족했다. [최종 검토의 판정과 인용](../evaluations/runs/2026-11-06-v0.7.0/forward/reviews/final.md)을 보존했다. 이 결과는 교정 후 완성본에 대한 판정이며, 위의 최초 생성 비교 결과를 대체하지 않는다.

### 문단 구조의 변화

| 사례 | v0.6.0 첫 제출의 최장 문단 | v0.7.0 첫 제출의 최장 문단 | v0.7.0 최종본의 최장 문단 |
| --- | ---: | ---: | ---: |
| 조사 보고서 | 227자 | 163자 | 163자 |
| 설계 검토 | 283자 | 144자 | 136자 |

편집 대상 초안의 최장 문단은 각각 912자와 476자였다. 설계 검토에서 250자를 넘는 일반 산문 토큰은 v0.6.0 첫 제출의 3개에서 현재 최종본의 0개로 바뀌었다. 첫 제출의 `(판단)`·`(추측)` 꼬리표는 v0.6.0에서 두 문서 합계 3개였고 v0.7.0에서는 0개였다.

전체 분량은 조사 보고서 1,953자→1,885자, 설계 검토 2,248자→2,362자다. 설계 검토는 근거를 별도로 배치하면서 전체 분량이 늘었지만 긴 경로가 문장을 끊는 부분은 줄었다. [산문 통계](../evaluations/runs/2026-11-06-v0.7.0/audit/report-structure.json)는 인라인 Markdown을 포함한 최상위 산문 토큰을 센 값이다. 목록·표·제목·코드는 별도 형식이며, 문단 길이는 편집 구조를 확인하는 보조 지표로 쓴다.

## 5. 재현과 배포

이번 배포 계약은 14개 사례, 필수 의미 201개, 독자 질문 57개를 포함한다. 기존 계약의 의무와 질문은 바꾸지 않고 새 두 사례를 추가했다. 이전 검토 재사용과 새 검토를 [실행 절차](../evaluations/runs/2026-11-06-v0.7.0/protocol.md)에 구분하고, 최종 출력·공개 예시·스킬 스냅샷의 해시를 [manifest](../evaluations/runs/2026-11-06-v0.7.0/manifest.json)에 연결한다.

비교 HTML에는 본문 36개와 입력 14개를 담는다. 기존 8개 사례는 과거 미적용 원문도 선택할 수 있다. 새 두 사례의 v0.6.0 출력은 이번 실행에서 작성한 비교본이며, 첫 제출의 판단과 최종 교정 이력을 [별도 비교](comparisons/new-topics.md)에 공개한다.

이번 확인은 문서의 의미·조건과 구조, 설치·화면 동작을 대상으로 한다. 사람의 읽는 시간·피로·기억과 반복 생성의 안정성은 별도 실험이 필요하다.
