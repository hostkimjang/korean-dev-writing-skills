## 끊긴 문장을 연결하기

**교정 전**

> 문서 번호로 캐시를 조회합니다. 캐시에 문서가 있으면 반환합니다. 캐시에 문서가 없으면 저장소에서 조회해 반환합니다. 저장소에서 조회한 문서는 캐시에도 저장합니다.

**교정 후**

> 문서 번호로 캐시를 조회합니다. 캐시에 문서가 있으면 반환하고, 없으면 저장소에서 조회해 반환합니다. 저장소에서 조회한 문서는 캐시에도 저장합니다.

두 분기를 함께 배치했다. 캐시 만료 시간, 저장소 종류, 성능 개선량 등 원문에 없는 정보는 더하지 않는다.

## 긴 문장을 나누기

**교정 전**

> 업로드가 실패하면 사용자가 파일을 다시 선택해야 했고, 이번 변경으로 선택한 파일을 유지하도록 했으며, 사용자가 취소 버튼을 누르면 선택을 해제하도록 했습니다.

**교정 후**

> 기존에는 업로드가 실패하면 사용자가 파일을 다시 선택해야 했습니다. 이번 변경으로 실패해도 선택한 파일을 유지합니다. 사용자가 취소 버튼을 누르면 선택을 해제합니다.

기존 동작, 변경 동작, 취소 조건을 나눴다. 실패 원인이나 표시되는 메시지는 새로 추가하지 않는다.

## 여러 중단 조건을 분리하기

**교정 전**

> 전송 허가의 유효기간이 지났거나, 대상 경로에 쓸 수 없거나, 원본과 전송 파일의 검증값이 다르면 전송을 중단하고 원본 파일을 보관합니다.

**교정 후**

다음 중 하나라도 해당하면 전송을 중단하고 원본 파일을 보관합니다.

- 전송 허가의 유효기간이 지났습니다.
- 대상 경로에 쓸 수 없습니다.
- 원본과 전송 파일의 검증값이 다릅니다.

조건을 각각 찾을 수 있게 나누고 공통 조치는 한 번 적었다. 세 조건을 모두 충족해야 중단하는 뜻으로 바꾸거나, 재시도 횟수·만료 시간을 새로 만들지 않는다. 실행 절에서 사용할 때는 원자료에 있는 허가의 유효기간과 기준 시각도 같은 위치에 둔다.

## 정보를 더할 때는 근거를 먼저 확인하기

**주어진 문장**

> 파일 목록을 읽는 속도가 개선되었습니다.

이 문장을 다듬는 작업만으로는 수치나 개선 방법을 알 수 없다. 실제 사용 경험을 강조한 문장이라면 과장 없이 유지하고, 정확한 수치가 필요한 보고서라면 측정 자료가 필요하다고 표시한다. 측정을 했다는 주장도 새로 만들지 않는다.

**추가로 제공된 측정 자료**

> 같은 장비에서 파일 2,000개의 목록을 읽는 시간을 10회 측정했다. 평균 시간은 변경 전 420ms, 변경 후 310ms였다.

**자료를 반영한 문장**

> 같은 장비에서 파일 2,000개의 목록을 읽는 시간을 10회 측정했습니다. 평균 시간은 420ms에서 310ms로 줄었습니다.

원자료의 평균값을 중앙값으로 바꾸거나, 다른 장비·파일 수에서도 같은 결과가 나온다고 확장하지 않는다.

## 시스템 기준과 확인 절차를 구분하기

**주어진 정보:** 내보내기 서버는 파일 기록을 마치면 상태를 `ready`로 바꾼다. 상태 조회는 현재 상태를 읽으며 작업을 진행시키지 않는다.

**적절한 설명:** 서버가 파일 기록을 마치면 상태가 `ready`가 됩니다. 결과를 확인할 때는 상태를 조회해 `ready`인지 확인하세요.

`ready`를 조회해야 파일 기록이 완료된다는 설명으로 바꾸지 않는다. 시스템의 완료 조건과 사람이 완료를 확인하는 행동은 다르다.

## 짧게 쓰면서 판단 한계의 이유 남기기

**주어진 정보:** 자작 백업 도구의 일부 작업 로그만 확보했다. 전체 작업의 성공률은 확인할 수 없다.

**적절한 설명:** 자작 백업 도구의 일부 로그만 있어 전체 성공률은 확인할 수 없습니다.

단순히 `성공률은 미확인입니다`라고 줄이면 대상과 판단 한계의 이유가 사라진다. 로그 비율이나 확보하지 못한 원인은 새로 만들지 않는다.
