# trace-slice

`trace-slice`는 로컬 JSON Lines 로그 파일에서 지정한 최소 심각도 이상의 항목을 골라 내는 CLI입니다. 로그에서 오류 항목을 찾아 터미널로 확인하거나 파일로 저장할 때 사용합니다. 로그를 네트워크로 전송하지 않습니다.

이 문서는 **0.4.2** 버전을 기준으로 설명합니다.

## 설치

프로젝트에서 선언한 Python 요구 버전은 **3.10 이상**입니다. 설치와 기본 동작을 확인한 환경은 **Ubuntu 22.04의 Python 3.11**이며, 다른 운영체제에서의 검증 기록은 없습니다.

버전을 고정해 설치합니다.

```bash
python -m pip install trace-slice==0.4.2
```

설치 후 다음 명령으로 도움말을 확인합니다.

```bash
trace-slice --help
```

## 첫 실행: 오류 항목 확인

입력으로 사용할 로컬 JSON Lines 로그 파일을 준비합니다. 각 정상 로그 행에는 `level` 필드가 있어야 합니다.

아래 예시는 로그 파일이 `./logs/api.jsonl`에 있는 경우입니다. 현재 디렉터리에서 해당 파일을 읽으므로, 실제 로그 위치가 다르면 경로를 바꿔 실행하세요.

```bash
trace-slice ./logs/api.jsonl --level error
```

이 명령은 `error` 항목을 표준 출력으로 내보냅니다. 입력 파일을 읽을 수 없거나 JSON 구문이 잘못된 행이 있을 때의 동작은 [입력 오류 처리](#입력-오류-처리)에서 확인할 수 있습니다.

## 결과를 파일로 저장

다음은 `./logs/api.jsonl`의 `error` 항목을 `./errors.jsonl`에 저장하는 예시입니다. 출력 경로는 원하는 파일로 바꿔 지정하세요. **지정한 파일이 이미 있으면 덮어씁니다.**

```bash
trace-slice ./logs/api.jsonl --level error --output ./errors.jsonl
```

## 사용 형식과 주요 옵션

```text
trace-slice INPUT [--level LEVEL] [--output PATH]
```

| 인수·옵션 | 설명 | 생략했을 때 |
| --- | --- | --- |
| `INPUT` | 읽을 로컬 JSON Lines 파일의 경로입니다. | 필수 위치 인수이므로 생략할 수 없습니다. |
| `--level LEVEL` | 출력할 최소 심각도입니다. | `info`를 사용합니다. |
| `--output PATH` | 결과를 `PATH`에 저장합니다. **파일이 이미 있으면 덮어씁니다.** | 결과를 표준 출력으로 내보냅니다. |

`--level`의 허용값은 `debug` → `info` → `warn` → `error`이며, 이 순서로 심각도가 높아집니다. 지정한 값과 그보다 높은 심각도의 항목을 출력하므로, `--level warn`을 지정하면 `warn`과 `error` 항목이 출력됩니다.

## 입력 오류 처리

로그 결과와 입력 오류 안내는 서로 다른 출력으로 나갑니다. 로그 결과는 표준 출력이나 `--output`으로 지정한 파일에 쓰고, 다음 오류 안내는 표준 오류로 내보냅니다.

| 상황 | 처리 방식 |
| --- | --- |
| JSON 구문이 잘못된 행이 있는 경우 | 해당 행을 건너뛰고, 건너뛴 행 수를 표준 오류로 알립니다. 이 이유만으로 실행이 실패하지는 않습니다. |
| `INPUT` 파일을 읽을 수 없는 경우 | 오류를 표준 오류로 알리고 **종료 코드 `2`**로 끝납니다. |

## 제한 사항

0.4.2에는 다음 기능이 없습니다.

- 실행 중 늘어나는 로그를 계속 따라가는 기능
- 날짜 범위를 지정하는 옵션
