# 달무리 설정배포 안내

달무리는 가상의 워크스페이스 설정배포 서비스다. 활성 설정 묶음은 워크스페이스당 최대 하나이며 사용자별로 다르게 적용할 수 없다.

## 권한과 초안 준비

조회자는 상태·이력을 본다. 편집자는 초안 작성·저장·검사를, 배포자는 적용 요청·예약 취소를 할 수 있으며 겸임도 가능하다.

초안에 작업 요청 기본 상한과 알림 휴지 시간대를 모두 입력해 유효성 검사를 한다. 통과 뒤 수정하면 결과가 무효이므로 다시 검사한다.

## 일반 적용과 첫 적용 예외

일반 적용은 검사 통과 초안을 골라 `activate_at`을 지정한다. 서버 접수 시각보다 5분 이상 뒤여야 하며 정확히 5분 뒤도 허용된다. 시각은 UTC다.

활성 묶음 이력이 없는 새 워크스페이스는 `UNCONFIGURED`다. 첫 적용 요청에만 `apply_now: true`를 쓸 수 있다. `activate_at`은 보내지 않고 5분 대기도 없다. 검사 통과·배포자 역할·기존 `SCHEDULED` 배포 없음은 필요하다.

수락하면 두 방식 모두 HTTP 202, 새 `release_id`, `state=SCHEDULED`를 반환한다. 적용 완료가 아니다.

## 접수 거절과 재요청

| 조건 | 반환·대응 |
| --- | --- |
| 검사 미통과·수정으로 결과 무효 | HTTP 422, `{"error":"BUNDLE_INVALID"}`. `release_id` 미발급 |
| 같은 워크스페이스에 `SCHEDULED` 배포 존재 | HTTP 409, `{"error":"PENDING_RELEASE_EXISTS"}`. 활성화·예약 취소 후 새 요청 가능 |
| 일반 `activate_at`이 서버 접수 시각보다 5분 미만 뒤 | HTTP 400, `{"error":"ACTIVATION_TOO_SOON"}` |
| 배포자 역할 없음(조회자·편집자도 해당) | HTTP 403, `{"error":"RELEASE_ROLE_REQUIRED"}` |
| 활성 묶음 이력이 있는데 `apply_now: true` 요청 | HTTP 409, `{"error":"INITIAL_MODE_NOT_ALLOWED"}` |

조건 중복 시 오류 우선순위는 미확인이다.

## 전환과 상태 확인

서버는 명목상 30초 주기로 평가한다. 일반 요청은 `activate_at` 도달 후 첫 평가, 초기 요청은 접수 후 첫 평가에서 `ACTIVE`로 전환한다. 30초는 완료 보장이 아니다. 전환 전 기존 묶음을 쓰며 첫 적용 대기 중인 워크스페이스는 `UNCONFIGURED`로 남는다.

응답의 `release_id`를 기록해 콘솔 배포 이력에서 상세를 연다. `release_id`, `state`, `activate_at`, `activated_at`을 살핀다. `state=ACTIVE`면 적용된 상태다. 초기 요청의 activate_at, 전환 전 activated_at은 비어 있다. 조회는 저장 상태만 읽으며 평가·활성화를 유발하지 않는다.

## 취소·복구와 평가 재개

접수한 묶음은 수정할 수 없다. 바꾸려면 `SCHEDULED`일 때 배포자가 콘솔에서 예약 취소하고 새 초안을 제출한다. 취소된 요청은 `CANCELLED`다. `ACTIVE`는 취소할 수 없으며, 이전 내용으로 되돌리려면 이전 묶음을 복사해 새 일반 적용을 요청한다.

평가 재개 시 저장된 SCHEDULED 요청과 원래 activate_at을 유지한다. 예정 시각이 지났다면 재개 후 첫 평가에서 전환 대상이 된다. 새 `release_id`를 발급하거나 5분 대기를 다시 계산하지 않으며 같은 `release_id` 상세에서 확인한다.
