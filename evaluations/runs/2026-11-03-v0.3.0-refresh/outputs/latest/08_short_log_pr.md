기존 개발용 합성 요청 로그에서 같은 `ticket_ref`의 `response_sent` 뒤에 `wait_elapsed`가 남은 사례를 관측했습니다. 정리와 만료 콜백의 실행 순서를 조사 중이나 원인과 안정적인 재현 조건은 미확정입니다. 실제 응답 유실·중복 처리 여부는 알 수 없고 빈도도 집계하지 않았습니다.

`worker/pending_slots.py`에 대기 항목 생성·제거·만료 콜백 진입 로그를 추가합니다. `diag_waits`가 켜졌을 때만 `ticket_ref`, `elapsed_ms`, 남은 항목 수만 기록합니다. 처리 동작은 바꾸지 않는 관측 보강입니다.

로컬 합성 요청 환경이 준비되지 않아 테스트와 변경 후 로그 수집을 하지 못했습니다. 가설과 변경 동작은 검증하지 못했습니다.
