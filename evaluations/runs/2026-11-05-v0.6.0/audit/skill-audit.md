# 한국어 개발 문서 작성 스킬 독립 검토

## 결론과 범위

`SKILL.md`, 참조 문서 세 개(`document-types.md`, `before-after-guide.md`, `reading-flow.md`), `agents/openai.yaml`을 모두 읽었다. 새 평가 과제의 내용이나 정답은 열지 않았다. 아래 위치는 수정 전 파일의 행 번호다.

현재 스킬은 독자의 목적, 전제와 지시 대상, 독립 조회, 실행 위치의 조건, 의미 보존, 발견한 문제의 실제 수정을 이미 다룬다. 이 영역에 새 점검 항목을 더할 근거는 부족하다. 수정은 `reading-flow.md`의 중복 통합과 독자 지식 기준의 명료화 두 곳으로 제한했다. 독자 피로 또는 이해도가 개선되었다는 실험 결과는 없으며, 아래 예상 결과는 검증할 가설이다.

## 보존할 우선순위와 장점

- **사실과 의미가 먼저다.** `SKILL.md:12`는 “사실·의미 보존 → 독자와 목적에 맞는 구조 → 문단의 흐름 → 자연스러운 문장 → 형식” 순서를 명시한다. 문장을 줄이기 위해 조건이나 예외를 버리지 않는 현재 우선순위를 유지한다.
- **자연스러운 연결을 이미 안내한다.** `SKILL.md:41–43`, `reading-flow.md:49–55`는 문단의 질문, 새 개념의 전제, 관계와 지시 대상, 짧게 나뉜 문장의 재결합을 다룬다. 연결어 목록이나 문장 길이 규칙을 추가할 필요가 없다.
- **찾아 읽는 사람을 고려한다.** `SKILL.md:45,47,69,73`, `reading-flow.md:22,44–45,52,60,64,80–83`은 제목·항목명, 일관된 이름, 가까운 조건·응답·예외, 독립 실행 단위를 명시한다. 정보 탐색이 빠져 있다고 볼 수 없다. 문서 종류에 따른 구성은 `document-types.md`가 별도로 제공한다.
- **설명 틀을 강제하지 않는다.** `document-types.md:3`의 “아래 소제목 흐름은 출발점이며 의무적인 목차가 아니다”와 `reading-flow.md:4,35`의 선택 적용·고정 기준 금지를 유지한다. `before-after-guide.md`의 유지 예시와 `agents/openai.yaml`의 의미 보존 중심 소개도 본문과 일치한다.
- **결과를 실제로 고치고 효과를 과장하지 않는다.** `SKILL.md:85,87`은 문제를 본문에 반영하고 불필요한 재작성을 멈추게 한다. `reading-flow.md:126,132`는 자체 점검을 독자 실험으로 보고하지 않도록 제한한다.

## 1. 재정리 지침의 중복을 통합한다 — 적용

### 원문 위치와 근거

`references/reading-flow.md:67–76`, §6에는 재정리 지침이 8개 있다. 이 가운데 다음 5개는 재정리의 위치·목적·범위를 겹쳐 설명한다.

> 69: 긴 설명 뒤에 다음 절의 전제가 되는 구분이나 현재 상태를 짧게 되짚을 수 있다. 앞 절 전체를 다시 요약하지 않는다.
>
> 70: 재정리에는 다음 행동이나 판단과의 관계를 붙인다. 앞에서 한 말을 다른 말로 반복하는 것만으로 새 문단을 만들지 않는다.
>
> 71: 이름·핵심 구분·판정 조건을 짚는 것으로 충분하면 이미 설명한 원리와 배경을 다시 풀지 않는다. 복수 조건과 예외를 전달해야 할 때는 한 문장 제한에 맞추느라 생략하지 않는다.
>
> 74: 독자가 흐름을 잃기 쉬운 전환, 실행 직전, 독립적으로 찾아 읽는 절처럼 현재 이해나 판단에 필요한 곳에서 재정리한다. 매 절에 개요·요약·결론을 강제하지 않는다.
>
> 75: 반복을 줄인 뒤에도 해당 절에서 해야 할 판단을 알 수 있는지 확인한다. 이름이나 핵심 조건의 필요한 반복과 설명 전체의 중복을 구분한다.

같은 원칙의 핵심은 `SKILL.md:63`에도 있다. 본문과 상세 참조의 일부 중복은 필요한 구조이므로 그 자체를 문제 삼지 않는다. 여기서는 한 참조 절 안에서 같은 판단을 여러 항목으로 나눈 부분만 합친다.

### 예상 결과와 한계

확인 가능한 문제는 지침 자체의 반복이다. 이 반복이 작성 과정에서 재정리를 과도하게 부각하거나 검토 부담을 늘릴 수 있다는 것은 가설이다. 통합의 목적은 새 의무 없이 같은 판단 기준을 더 적은 항목으로 전달하는 것이다. 실제 문서에서 반복이 줄어드는지는 새 작업으로 확인해야 한다.

### 최소 수정안

위 5개 항목을 아래 2개로 교체한다. 기존 72행의 실행 직전·독립 조회 조건, 73행의 확실성 보존, 76행의 표 해설 기준은 그대로 둔다. §6 전체는 8개에서 5개 항목이 된다.

> 독자가 흐름을 잃기 쉬운 전환이나 긴 설명 뒤에서는 다음 절에 필요한 구분이나 상태를 짧게 되짚고, 다음 이해·행동·판단과의 관계를 밝힌다. 앞 절 전체를 다시 요약하거나 매 절에 개요·요약·결론을 붙이지 않는다.
>
> 이름·핵심 구분·판정 조건으로 충분하면 이미 설명한 원리와 배경을 다시 풀지 않는다. 반복을 줄인 뒤에도 해당 절의 판단에 필요한 내용이 남아 있는지 확인하고, 복수 조건과 예외를 문장 수에 맞춰 생략하지 않는다.

### 새 작업에서 확인할 방법

수정 전후 스킬에 동일한 새 원자료와 작성 요청을 각각 제공한다. 작성자에게 이 진단이나 예상 답을 전달하지 않는다. 결과에서 전환 문장이 다음 절의 이해에 필요한 구분을 연결하는지, 앞의 원리·배경을 반복하기만 하는 문단이 있는지 확인한다. 이어 독립 조회 절의 필수 조건과 복수 조건·예외가 원자료대로 남았는지 대조한다. 단순한 글자 수 감소를 개선으로 판정하지 않는다.

## 2. 독자의 익숙함을 문서의 개념·동작 기준으로 명시한다 — 적용

### 원문 위치와 근거

`references/reading-flow.md:24–25`, §1:

> 처음 접하는 독자에게는 설명에 필요한 개념과 전제를 먼저 소개한다. 여러 약어와 구성 요소를 한꺼번에 정의한 뒤 오래 기억하게 하지 않는다.
>
> 익숙한 독자에게는 기초 지식을 반복하기보다 현재 문서에서 달라지는 동작·조건·판단을 설명한다.

독자에 따른 깊이 조정은 이미 있다. 다만 “처음 접하는”과 “익숙한”의 대상이 생략되어 있다.

### 예상 결과와 한계

개발 경험이 많은 독자라도 해당 프로젝트의 개념과 동작은 모를 수 있다. 일반적인 숙련도를 해당 주제의 사전 지식으로 간주하면 필요한 전제가 빠질 가능성이 있다. 반대로 설명 대상에 익숙한 독자에게 일반적인 기초 설명을 과도하게 붙일 수도 있다. 이는 원문 표현에서 도출한 해석 위험이며, 실제 발생한 오류라는 주장은 아니다.

### 최소 수정안

두 항목의 시작만 다음과 같이 바꾼다. 독자 분류나 질문 절차는 추가하지 않는다.

- “처음 접하는 독자에게는” → “이 문서의 개념·동작이 낯선 독자에게는”
- “익숙한 독자에게는” → “이 문서의 개념·동작에 익숙한 독자에게는”

### 새 작업에서 확인할 방법

같은 주제의 새 작성 요청에 독자 맥락을 명확히 제공하되, 하나는 개발 경험은 있지만 해당 시스템을 처음 접하는 독자, 다른 하나는 해당 시스템을 이미 사용하는 독자로 설정한다. 앞의 경우 판단에 필요한 프로젝트 전제가 설명되는지, 뒤의 경우 이미 공유한 기초 설명을 되풀이하지 않고 달라지는 동작과 조건에 집중하는지 확인한다. 두 결과 모두 원자료의 제약과 불확실성을 보존해야 한다.

## 추가하지 않은 규칙

일반적인 정보 탐색 점검, 명령 위치의 선행조건, 전제의 가까운 배치, 문단 연결, 실제 교정 완료를 별도 항목으로 다시 추가하지 않았다. 해당 안내는 이미 충분하다. 근거 없는 글자 수·읽기 시간·집중시간 기준, 특정 표현의 금지 규칙, 새 평가 사례에만 맞는 예시도 추가하지 않았다.

## 변경과 검증 범위

배포 파일 변경은 `skills/korean-dev-writing/references/reading-flow.md` 한 파일의 두 부분뿐이다. `SKILL.md`, 나머지 참조 문서 두 개, `agents/openai.yaml`은 변경하지 않았다. 새 과제 작성 비교와 독자 평가는 이 감사 결과에 포함하지 않는다. 이 보고서는 편집 가설과 최소 수정의 근거를 기록하며, 효과 입증을 대신하지 않는다.
