## 끊긴 문장을 연결하기

**교정 전**

> 문서 번호로 캐시를 조회합니다. 캐시에 문서가 있으면 반환합니다. 캐시에 문서가 없으면 저장소에서 조회해 반환합니다. 저장소에서 조회한 문서는 캐시에도 저장합니다.

**교정 후**

> 문서 번호로 캐시를 조회합니다. 캐시에 문서가 있으면 반환하고, 없으면 저장소에서 조회해 반환합니다. 저장소에서 조회한 문서는 캐시에도 저장합니다.

두 분기를 함께 배치했습니다. 캐시 만료 시간, 저장소 종류, 성능 개선량 등 원문에 없는 정보는 더하지 않습니다.

## 긴 문장을 나누기

**교정 전**

> 업로드가 실패하면 사용자가 파일을 다시 선택해야 했고, 이번 변경으로 선택한 파일을 유지하도록 했으며, 사용자가 취소 버튼을 누르면 선택을 해제하도록 했습니다.

**교정 후**

> 기존에는 업로드가 실패하면 사용자가 파일을 다시 선택해야 했습니다. 이번 변경으로 실패해도 선택한 파일을 유지합니다. 사용자가 취소 버튼을 누르면 선택을 해제합니다.

기존 동작, 변경 동작, 취소 조건을 나눴습니다. 실패 원인이나 표시되는 메시지는 새로 추가하지 않습니다.

## 여러 중단 조건을 분리하기

**교정 전**

> 전송 허가의 유효기간이 지났거나, 대상 경로에 쓸 수 없거나, 원본과 전송 파일의 검증값이 다르면 전송을 중단하고 원본 파일을 보관합니다.

**교정 후**

다음 중 하나라도 해당하면 전송을 중단하고 원본 파일을 보관합니다.

- 전송 허가의 유효기간이 지났습니다.
- 대상 경로에 쓸 수 없습니다.
- 원본과 전송 파일의 검증값이 다릅니다.

조건을 각각 찾을 수 있게 나누고 공통 조치는 한 번 적었습니다. 세 조건을 모두 충족해야 중단하는 뜻으로 바꾸거나, 재시도 횟수·만료 시간을 새로 만들지 않습니다. 실행 절에서 사용할 때는 원자료에 있는 허가의 유효기간과 기준 시각도 같은 위치에 둡니다.

## 정보를 더할 때는 근거를 먼저 확인하기

**주어진 문장**

> 파일 목록을 읽는 속도가 개선되었습니다.

이 문장을 다듬는 작업만으로는 수치나 개선 방법을 알 수 없습니다. 실제 사용 경험을 강조한 문장이라면 과장 없이 유지하고, 정확한 수치가 필요한 보고서라면 측정 자료가 필요하다고 표시합니다. 측정을 했다는 주장도 새로 만들지 않습니다.

**추가로 제공된 측정 자료**

> 같은 장비에서 파일 2,000개의 목록을 읽는 시간을 10회 측정했습니다. 평균 시간은 변경 전 420ms, 변경 후 310ms였습니다.

**자료를 반영한 문장**

> 같은 장비에서 파일 2,000개의 목록을 읽는 시간을 10회 측정했습니다. 평균 시간은 420ms에서 310ms로 줄었습니다.

원자료의 평균값을 중앙값으로 바꾸거나, 다른 장비·파일 수에서도 같은 결과가 나온다고 확장하지 않습니다.

## 시스템 기준과 확인 절차를 구분하기

**주어진 정보:** 내보내기 서버는 파일 기록을 마치면 상태를 `ready`로 바꿉니다. 상태 조회는 현재 상태를 읽으며 작업을 진행시키지 않습니다.

**적절한 설명:** 서버가 파일 기록을 마치면 상태가 `ready`가 됩니다. 결과를 확인할 때는 상태를 조회해 `ready`인지 확인하세요.

`ready`를 조회해야 파일 기록이 완료된다는 설명으로 바꾸지 않습니다. 시스템의 완료 조건과 사람이 완료를 확인하는 행동은 다릅니다.

## 짧게 쓰면서 판단 한계의 이유 남기기

**주어진 정보:** 자작 백업 도구의 일부 작업 로그만 확보했습니다. 전체 작업의 성공률은 확인할 수 없습니다.

**적절한 설명:** 자작 백업 도구의 일부 로그만 있어 전체 성공률은 확인할 수 없습니다.

단순히 `성공률은 미확인입니다`라고 줄이면 대상과 판단 한계의 이유가 사라집니다. 로그 비율이나 확보하지 못한 원인은 새로 만들지 않습니다.

## 여러 발견이 섞인 문단을 나누기

**교정 전**

> 은행나무 변환기의 야간 입력은 120개이며 필수 필드가 없는 8개를 제외한 112개를 저장했습니다. 제외한 입력은 실패 목록에서 확인합니다. 별도 실험 서버에서는 변환기 단독 지연을 1,000회 측정했으며 CPU 2스레드의 p50은 12ms였습니다. 이 값은 지연 시간 측정이며 정확도나 전체 작업 완료 시간은 아닙니다. 저장소 후보는 운영 인력과 비용을 고려해 솔잎 저장소를 첫 실증 대상으로 권한다(판단). 아직 채택하거나 설치한 것은 아닙니다. 실증 일정은 정해지지 않았습니다.

**교정 후**

### 1. 야간 입력 120개 중 112개 저장

은행나무 변환기는 필수 필드가 없는 8개를 제외한 112개를 저장했습니다. 제외한 입력은 실패 목록에서 확인합니다.

### 2. 별도 실험 서버에서 변환기 단독 지연 측정

변환기 단독 지연을 1,000회 측정했습니다. CPU 2스레드의 p50은 12ms였습니다.

### 3. 솔잎 저장소를 첫 실증 대상으로 권장

운영 인력과 비용을 고려해 솔잎 저장소를 첫 실증 대상으로 권장합니다. 실증 일정은 정해지지 않았습니다.

운영 결과, 별도 환경의 측정, 제안을 구획으로 나눴습니다. 제목에서도 환경과 제안 상태를 유지했으며 실증을 확정 도입으로 바꾸지 않았습니다. 연결된 설명을 한 문장씩 흩어 놓지는 않습니다.

## 긴 근거를 문장 밖으로 옮기기

**교정 전**
