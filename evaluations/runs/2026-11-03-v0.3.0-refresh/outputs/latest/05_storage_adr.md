# ADR-007: 이벤트 중복 판정 저장소

- 작성일: 2026-10-15
- 상태: 제안
- 검토 상태: 데이터 및 운영 담당자의 검토가 아직 끝나지 않았다.

이벤트 API의 중복 판정 기록을 PostgreSQL의 `event_receipts` 테이블에 저장할 것을 제안한다. `(tenant_id, event_id)`에 유일성 제약을 두고, 중복 판정 기록과 업무 이벤트 생성을 같은 데이터베이스 트랜잭션에서 처리한다. 기존 PostgreSQL의 트랜잭션을 활용하고 별도 Redis 운영을 추가하지 않는 것이 제안의 주요 근거다.

## 배경과 요구사항

기존 이벤트 API는 PostgreSQL에 업무 이벤트를 저장한다. 같은 `tenant_id`에서 같은 `event_id`가 다시 제출되면 업무 이벤트가 중복 생성되지 않아야 한다. 서로 다른 `tenant_id`에서는 같은 `event_id`를 사용할 수 있으므로, 중복 판정 기준은 두 값의 조합이다.

과거 이벤트를 다시 가져오는 작업도 중복 판정 대상이다. 다만 중복 판정 기록을 얼마나 오래 보관할지는 아직 정하지 않았다. 보존 정책을 정할 때는 과거 이벤트의 재수집을 포함해 중복 방지가 필요한 범위를 함께 검토해야 한다.

## 제안하는 처리 방식

PostgreSQL에 `event_receipts` 테이블을 만들고 `(tenant_id, event_id)`에 유일성 제약을 설정한다. 요청은 다음 원칙에 따라 처리한다.

- 새 키에 대한 중복 판정 기록과 업무 이벤트 생성은 같은 데이터베이스 트랜잭션에서 처리한다.
- 중복 키가 이미 있으면 업무 이벤트를 새로 만들지 않는다.
- 데이터베이스 작업이 실패하면 요청에 `503`을 반환한다. 클라이언트는 같은 `tenant_id`와 `event_id`로 재시도한다.

## 검토한 대안과 제안 이유

비교한 대안은 Redis에 중복 판정 키를 저장하고 TTL을 두는 방식이다.

| 비교 기준 | PostgreSQL의 `event_receipts` 사용 | Redis에 키와 TTL 저장 |
| --- | --- | --- |
| 업무 이벤트 생성과의 원자적 처리 | 중복 판정 기록과 업무 이벤트 생성을 같은 데이터베이스 트랜잭션에서 처리한다. | PostgreSQL의 업무 이벤트 생성과 원자적으로 처리하려면 추가 설계가 필요하다. |
| 과거 이벤트의 중복 판정 | 중복 판정 기록의 보존 기간과 정리 정책을 정해야 한다. | TTL 만료 또는 키 유실 뒤 과거 이벤트가 다시 들어오면 중복을 놓칠 수 있다. |
| 저장소 운영 | 기존 PostgreSQL을 사용하므로 별도 Redis 운영을 추가하지 않는다. | Redis 운영이 추가된다. |

이 요구사항에서는 과거 이벤트를 다시 가져올 때도 중복을 판정해야 한다. Redis의 TTL 방식은 키가 사라진 뒤의 재수집을 다루어야 하고, PostgreSQL에 저장하는 업무 이벤트와의 원자적 처리도 별도로 설계해야 한다. PostgreSQL 제안은 기존 데이터베이스의 트랜잭션으로 두 기록을 함께 처리할 수 있다는 점에서 적합하다고 판단한다. 다만 이 방식도 보존 정책이 정해져야 중복 판정의 시간적 범위를 확정할 수 있다.

## 도입 시 감수할 점과 검증의 한계

`event_receipts`를 도입하면 기존 PostgreSQL의 쓰기와 인덱스 부하가 늘어난다. 중복 판정 기록을 정리하는 정책도 마련해야 한다. 기록 정리는 과거 이벤트의 중복 판정에 영향을 주므로, 보존 기간과 함께 결정해야 한다.

현재 부하에서 `event_receipts`의 추가 비용을 측정한 결과는 없다. 공식 지연 목표나 처리량 보장도 이번 ADR에서는 정하지 않았다. 따라서 성능 적합성은 검증이 필요한 사항으로 남는다.

## 승인 전에 결정할 사항

| 항목 | 리뷰에서 결정할 내용 |
| --- | --- |
| 보존 정책 | 중복 판정 기록을 얼마나 오래 보관하고 언제 정리할지 정한다. 과거 이벤트 재수집에 대한 중복 방지 요구와 정책이 맞는지 검토한다. |
| 성능 검증 계획 | 현재 부하에서 `event_receipts` 추가에 따른 쓰기·인덱스 부하와 비용을 어떻게 측정하고 평가할지 정한다. |
| 운영 책임 주체 | 도입 후 중복 판정 기록과 정리 정책의 운영을 누가 담당할지 정한다. |

리뷰에서 위 사항을 정한 뒤 제안의 승인 여부를 결정한다. 데이터 및 운영 담당자의 검토가 완료되기 전까지 이 문서의 상태는 제안이다.
