# 단풍 로그 보관·삭제·조회 안내

단풍 로그 보관기는 개발 로그를 빠른 조회용 `hot`과 장기 보관용 `archive`에 저장합니다. 기본 검색은 `hot`만 조회하며, `archive`의 로그는 복원 요청 후 조회할 수 있습니다. 로그의 보관 기한, 정리 작업의 처리 시각, 복원 사본의 만료 시각을 구분하면 로그가 검색되지 않는 이유와 앞으로 처리될 대상을 판단하는 데 도움이 됩니다.

## 보관 기간은 서버 수신 시각부터 계산

보관 기간의 기준은 서버가 로그를 받은 UTC 시각인 `received_at`입니다. 로그 본문의 `event_time`은 사건이 발생한 시각을 기록하는 값이며 보관 기간 계산에는 쓰지 않습니다. 로그를 조회해도 `received_at`과 보관 기한은 바뀌지 않습니다.

현재 정책의 처리 기준은 다음과 같습니다.

- **보관 이동:** `received_at`부터 14일 이상 지난 로그는 `archive` 이동 대상이 됩니다.
- **삭제:** 같은 `received_at`부터 60일 이상 지난 로그는 삭제 대상이 됩니다. 삭제 기한은 `archive`로 이동한 날을 기준으로 다시 계산하지 않습니다.

두 기준 모두 경계 시각을 포함합니다. 수신 후 정확히 14일이 되는 시각부터 이동 기준을, 정확히 60일이 되는 시각부터 삭제 기준을 충족합니다.

### 현재 정책을 적용한 시각 예시

다음 로그는 사건 발생 시각보다 서버 수신 시각이 늦습니다. 이동·삭제 기준은 서버 수신 시각에 맞춰 계산합니다.

| 항목 | UTC 시각 |
| --- | --- |
| 사건 발생 시각 `event_time` | `2026-09-26T07:00:00Z` |
| 서버 수신 시각 `received_at` | `2026-10-01T10:00:00Z` |
| 14일 경과: 이동 기준 충족 | `2026-10-15T10:00:00Z` |
| 60일 경과: 삭제 기준 충족 | `2026-11-30T10:00:00Z` |

표의 14일·60일 경과 시각은 처리 대상이 되는 기준입니다. 실제 이동이나 삭제가 완료되는 시각을 뜻하지는 않습니다.

## 정책 변경은 변경 이후 수신 로그에 적용

각 로그에는 수신 당시의 `policy_revision`과 보관 기준이 함께 저장됩니다. 정책이 바뀌면 변경 이후에 수신한 로그부터 새 정책을 적용하며, 기존 로그의 기한은 다시 계산하지 않습니다. 따라서 기존 로그의 보관 기한을 확인할 때는 그 로그에 저장된 보관 기준을 사용합니다.

## 이동·삭제는 매일 UTC 02:00 정리 작업에서 처리

정리 작업은 매일 UTC 02:00에 실행되어 보관 이동과 삭제를 처리합니다. 로그가 14일 또는 60일 기준을 충족하는 순간에 처리가 완료되는 것은 아닙니다. 작업이 지연되면 처리도 뒤로 미뤄질 수 있으며, 완료 시각은 보장되지 않습니다.

### `legal_hold=true`이면 삭제 제외

`legal_hold=true`인 로그는 삭제 대상에서 제외됩니다. 다만 `archive` 이동과 보관 기간의 경과는 계속됩니다. 보류 상태에서도 수신 후 60일 기준 시각은 그대로 유지됩니다.

보류를 해제했을 때 이미 `received_at`부터 60일 이상 지났다면 해당 로그는 다음 정리 작업의 삭제 대상이 됩니다. 보류 해제로 보관 기간이 새로 시작되지는 않습니다.

## 기본 검색에서 보이지 않는 로그 조회

기본 검색은 `hot`만 조회하므로 검색 결과에 로그가 없다는 사실만으로 `archive`에도 없거나 이미 삭제됐다고 판단할 수 없습니다. `archive`의 로그를 확인하려면 **보관 조회 화면**에서 대상 로그의 복원을 요청합니다.

복원은 `archive` 원본을 바탕으로 조회용 임시 사본을 만드는 작업입니다. 임시 사본은 **생성 완료 시점부터 24시간** 동안 유지되며, 만료 시각은 화면의 `restore_expires_at`에서 확인합니다.

임시 사본의 만료는 원본 삭제를 뜻하지 않습니다. 복원을 요청해도 원본의 보관 기간은 연장되지 않으므로, 원본의 삭제 대상 여부는 해당 로그의 보관 기준과 `legal_hold` 상태로 판단합니다.

## 아직 확인되지 않은 동작

정리 실패 시 복구 절차, 복원 완료까지 걸리는 시간, 삭제된 로그의 복구 가능성은 아직 확인되지 않았습니다.
