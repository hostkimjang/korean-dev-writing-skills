# v0.4.0: 의미 보존과 찾아보기 점검

실행일: 2026-11-03 (Asia/Seoul). 기존 여덟 사례의 현재 적용 문서를 갱신하고, 새 가상 사례 두 개에서 이전 지침과 새 지침의 출력을 비교한다. 사용자 전달 리뷰의 제안을 원자료와 대조한 뒤 지침을 보완했다. 특정 출력의 문제가 지침 충돌에서 발생했다는 인과관계를 전제로 하지 않는다.

## 생성 전에 고정하는 자료

- 공개된 v0.3.0의 기준 커밋은 `6202f14aa08cbc9ddda6bd0ffd62bbbf022033ac`이다. 기존 스킬 여섯 파일과 v0.4.0 후보 여섯 파일을 `snapshots/`에 그대로 보관한다.
- 기존 여덟 입력은 앞선 실행의 공통 입력과 바이트 단위로 같다. v0.3.0의 여덟 출력은 `2026-11-03-v0.3.0-refresh` 실행 원문을 재사용한다. 미적용 원문은 공개 비교의 참고 자료로 유지한다.
- 새 두 사례는 후보 스킬과 기존 평가 원문을 읽지 않은 별도 작성자가 작성했다. 설정배포 안내와 짧은 작업 보고를 사용하며 원자료·요청·평가 기준을 생성 전에 고정한다. 사용 요청 자체에 탐색이나 검증 범위의 구분이 명시돼 있으므로, 최소한의 요청에서도 같은 결과가 나오는지 입증하는 사례는 아니다.
- `evaluations/contracts/preservation-v1.json`은 이번 실행부터 사용하는 평가 계약이다. 기존 필수 명제와 `must_preserve` 범위를 유지하면서 따로 누락될 수 있는 대상·조건·근거·검증 상태를 세분화한다. 선택 명제를 필수로 조용히 바꾸지 않는다. 과거 출력에 대한 판정도 이 새 계약의 재검토로 저장하며 과거 점수를 수정하지 않는다.
- 원자료, 공통 입력, 계약, 스킬, 이 프로토콜의 SHA-256을 `manifest.json`에 기록한 뒤 생성을 시작한다.

## 생성 범위와 독립성

기존 여덟 사례에서 v0.4.0 출력 여덟 개를 새로 작성한다. 새 두 사례에서는 v0.3.0과 v0.4.0을 각각 한 번 작성한다. 새 출력은 총 열두 개다. 기존 사례의 두 조건은 생성 시점이 다르고, 새 두 사례의 두 조건은 이번 실행에서 함께 생성한다. 모든 조건을 다시 생성한 대규모 실험이 아니다.

각 `사례 × 생성 조건`은 별도의 새 컨텍스트를 사용한다. 생성자는 배정된 공통 입력과 해당 조건의 스킬만 읽는다. 평가 계약, 필수 항목, 독자 질문·기대 답, 이전 출력, 검토 결과와 의도한 개선점은 제공하지 않는다. 입력은 독자·목적·요청·원자료·있는 경우 초안만으로 만든다. 기존 입력은 재조합하지 않고 그대로 복사한다.

같은 세션 계열 모델을 상속하며 정확한 배포 식별자와 샘플링 설정은 노출되지 않는다. 결과가 아쉽다는 이유로 재생성하거나 후편집하지 않는다. 도구 실패로 사용 가능한 출력이 없을 때만 재시도하고 사유를 남긴다. 가상 설치·운영 명령을 실행하지 않는다.

## 자동 신호와 의미 판정을 구분한다

자동 검사기는 계약의 구조·ID·참조·해시, 문서 및 검토 행의 완결성, 인용의 원문 일치를 검사한다. 지정한 문자열이 있는지와 문자 수를 별도 신호로 기록한다. 문자열 존재를 의미 보존으로, 부재를 사실 누락이나 치명적 오류로 자동 판정하지 않는다. 조건·부정·인과관계는 실제 문맥에서 검토한다.

출력을 고정한 뒤 두 조건의 표시 순서와 라벨을 무작위로 정한다. 검토자는 원자료·평가 계약과 익명 출력만 읽고, 스킬·조건 대응표·이전 리뷰는 받지 않는다. 기존 여덟 사례의 미적용 원문은 이번 의미 재검토에 포함하지 않으며, 앞선 검토가 있는 참고 문서로 표시한다.

- 필수 의미마다 **보존·부분보존·누락·충돌** 중 하나와 정확한 근거 구절·이유를 기록한다. 포괄 요약과 동의어를 허용하며 원문 표현 복제를 요구하지 않는다. 선택 항목은 생략할 수 있으나 포함했다면 충돌을 검토한다.
- 탐색 질문에는 답의 충족 여부, 진입한 제목·표·문단, 추가로 읽어야 하는 위치, 그 절에 빠진 전제와 정확한 인용을 적는다. 전역 사실 누락과 부분 조회의 불편을 구분한다.
- 치명적 오류는 사용·운영·검증 판단을 뒤집는 근거가 있을 때 별도로 기록한다. 대상명 생략이나 작은 표현의 모호함만으로 자동 판정하지 않는다.
- 자연스러운 한국어, 설명의 연결, 필요한 재환기와 배경의 반복, 짧은 문서의 형식은 실제 구절을 들어 정성적으로 기록한다. 총점이나 길이 감소 점수는 만들지 않는다.

검토 결과를 고정한 뒤에만 조건 대응표를 공개한다. 집계표는 판정 기록의 요약이며 독자 효과나 모델 성능 점수가 아니다. 원자료를 함께 본 모델 검토는 이해·기억·탐색 시간·피로를 측정한 독자 실험이 아니다.

## 보고와 한계

지침 보완의 근거와 조정한 제안, 기존 여덟 사례의 전후 원문, 새 두 사례의 조건별 원문, 자동 신호와 익명 검토를 연결한다. 불리한 결과와 차이가 작은 결과도 남긴다. 생성·검토 중 발견한 출력을 수정해 같은 실행의 성공 사례로 바꾸지 않는다.

단회 생성, 같은 모델 계열의 작성·검토, 기존 사례의 시점 차이, 문제 유형을 고려해 새 사례를 설계했다는 한계가 있다. 이번 결과만으로 지침 충돌의 인과관계, 반복 생성의 안정성, Claude·Gemini에서의 효과 또는 실제 독자의 읽기 부담 개선을 확정하지 않는다.
