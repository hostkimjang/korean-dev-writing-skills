# 긴 문서 독립 검토 — v0.5.0 round-1

평가 패킷의 원자료·작성 요청과 최종 후보 세 문서를 대조했다. 필수 요구사항 **38개 모두 보존**, 선택 항목 **4개 모두 보존**, 독자 질문 **6개 모두 충분**으로 판정했다. 지정된 수정 확인 항목 **4개는 모두 해결**됐으며, 하드 실패와 남은 수정 요구는 없다.

## 유지할 내용

- **이벤트 수집 아키텍처:** `202`의 큐 수락 경계, 응답과 별개인 DB 기록, DB 성공 뒤 offset 커밋, 중복 전달 가능성과 `event_id` 유일성 제약의 저장 범위가 일관된다. 장애 표 앞의 식별자 유지 조건과 원인별 재처리 표는 그대로 유지한다. 미확정 보존·성능·복구 목표와 상태 조회 API 부재도 명확하다.
- **장애 런북:** 배포와 적체의 관계 및 `current`·`stable` 차이를 확인한 뒤 실행하도록 한 분기, `state=paused`와 `inflight=0`의 동시 확인, 성공한 롤백 뒤에만 재개하는 순서를 유지한다. pause 반환 의미와 요청 후 5분의 중단 기준이 롤백 명령과 같은 실행 절에 모여 있다. 마지막 이관 표는 조건과 중단 행동을 직접 대응시킨다.
- **저장소 ADR:** 미승인 제안 상태, tenant 범위의 복합 키, 중복 판정 기록과 업무 이벤트 생성의 동일 트랜잭션을 유지한다. Redis 비교에는 TTL 만료·키 유실 뒤 과거 이벤트 재반입이라는 조건과 PostgreSQL 업무 이벤트 생성의 원자성 범위가 명시돼 있다. 표 다음 문장은 중복 나열을 줄이고 요구사항을 제안 이유에 연결한다. 승인 조건 절에서 비용 미측정·목표 미설정과 남은 보존·검증 계획·운영 책임 결정을 함께 확인할 수 있다.

## 수정 필요

추가 수정은 요구하지 않는다. 지정된 `FIX-RUNBOOK-ROLLBACK`, `FIX-RUNBOOK-ESCALATION`, `FIX-ADR-REPETITION`, `FIX-ADR-APPROVAL`은 모두 수용 조건을 충족했다. 실행 직전의 조건 재확인과 이관용 요약은 독자의 진입 위치에 필요한 역할을 하므로 중복이라는 이유로 제거할 대상이 아니다.
