# 달무리 설정배포 안내

달무리는 작업 요청의 기본 상한과 알림 휴지 시간대를 배포하는 가상 서비스입니다. 활성 묶음은 워크스페이스당 최대 하나이며, 사용자별 적용은 없습니다.

## 1. 권한·초안 준비

조회자는 배포 상태·이력을 보고, 편집자는 초안 작성·저장·유효성 검사를 할 수 있습니다. 적용 요청·예약 취소에는 배포자 역할이 필요합니다. 역할은 겸할 수 있습니다.

초안에 두 설정을 모두 입력하고 검사합니다. 통과 후 수정하면 결과가 무효가 되므로 다시 검사합니다. 기존 `SCHEDULED` 배포가 있으면 활성화나 예약 취소 후 새 요청을 보냅니다.

## 2. 일반·초기 전용 요청

일반 적용은 검사를 통과한 초안과 `activate_at`을 지정합니다. 시각은 UTC이며 서버 접수 시각보다 5분 이상 뒤여야 합니다.

활성 묶음 이력이 없는 새 워크스페이스는 `UNCONFIGURED`입니다. 이 상태의 첫 적용 요청에만 `apply_now: true`를 쓸 수 있습니다. `activate_at`은 보내지 않고 5분 대기도 없습니다. 검사 통과와 배포자 역할은 필요하며, 기존 `SCHEDULED` 배포도 없어야 합니다.

두 모드 모두 접수 응답은 HTTP 202, 새 `release_id`, `state: SCHEDULED`입니다. 접수는 적용 완료가 아닙니다.

## 3. 실제 적용·상태 조회

서버는 명목상 30초마다 전환을 평가합니다. 일반 요청은 예정 시각 도달 후, 초기 요청은 접수 후 첫 평가에서 `ACTIVE`가 됩니다. 30초 내 완료를 보장하지는 않습니다. 전환 전에는 기존 묶음이 쓰이고, 새 워크스페이스는 `UNCONFIGURED`를 유지합니다.

`release_id`를 기록하고 콘솔 배포 이력에서 해당 상세를 엽니다. 이 ID와 `state`, `activate_at`, `activated_at`을 확인합니다. 초기 요청의 `activate_at`, 전환 전 `activated_at`은 비어 있습니다. 조회는 저장된 상태를 읽을 뿐 평가나 활성화를 유발하지 않습니다.

## 4. 취소·복구·평가 재개

접수된 내용은 수정할 수 없습니다. 변경하려면 `SCHEDULED`일 때 배포자가 콘솔에서 예약 취소해 `CANCELLED`로 만든 뒤 새 초안을 제출합니다. `ACTIVE`는 예약 취소할 수 없습니다. 이전 내용으로 되돌리려면 이전 묶음을 복사해 새 일반 적용을 요청합니다.

평가 재개 시 저장된 `SCHEDULED` 요청과 원래 `activate_at`을 이어 씁니다. 시각이 지났다면 첫 평가의 전환 대상입니다. 새 ID 발급이나 5분 대기 재계산 없이 같은 `release_id`의 상세에서 확인합니다.

## 접수 거절

| 조건 | HTTP | 응답 본문 |
| --- | --- | --- |
| 검사 미통과·수정으로 검사 무효 | 422 | `{"error":"BUNDLE_INVALID"}` |
| 같은 워크스페이스에 `SCHEDULED` 배포 있음 | 409 | `{"error":"PENDING_RELEASE_EXISTS"}` |
| 일반 적용 시각이 서버 접수 후 5분 미만 | 400 | `{"error":"ACTIVATION_TOO_SOON"}` |
| 배포자 역할 없음 | 403 | `{"error":"RELEASE_ROLE_REQUIRED"}` |
| 활성 묶음 이력이 있는데 `apply_now: true` 요청 | 409 | `{"error":"INITIAL_MODE_NOT_ALLOWED"}` |

검사 거절 시 `release_id`는 미발급입니다. 거절 조건이 겹칠 때 오류 우선순위는 자료에 없습니다.
