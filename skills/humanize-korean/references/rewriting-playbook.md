# 개발 문서 교정 절차

이 절차는 개발 안내·현행 명세·검증 기록을 파일 단위로 읽고 직접 교정할 때 적용합니다. [빠른 규칙](quick-rules.md), [상세 분류](ai-tell-taxonomy.md), [정본 매핑](development-rules.json)을 먼저 읽습니다. 일반 한국어 문장 작업에서는 [기본 절차](core-workflow.md)를 함께 적용합니다.

## 1. 전체 범위와 기준본 확보

요청받은 디렉터리의 Markdown 파일을 전부 목록화하고 연결된 안내 문서를 확인합니다. 루트 `README.md`, `tests/README.md` 등은 실제로 존재하는 경우 대상에 포함합니다. 샘플 파일 몇 개만 읽고 나머지 문서에 같은 상태가 적용된다고 추정하지 않습니다.

각 파일을 현행 명세, 설명형 검증·인계 기록, 원본 보존용 사본으로 분류합니다. 보존용 사본은 수정 대상에서 제외하고 제외 이유를 기록합니다. 이름에 archive가 있다는 사실만으로 결정하지 말고 파일의 역할을 확인합니다.

수정 전 파일별 코드 블록·링크 대상·헤더·명시적 앵커·식별자·수치·날짜·해시·UUID를 기록합니다. 기존 작업 변경이 있으면 이 기준본에 포함하고, 다른 사람의 수정을 되돌리지 않습니다.

## 2. 보호 구간과 설명문 구분

코드 블록의 명령·주석·출력은 그대로 보존합니다. API 경로·필드명·환경변수·CLI 옵션·포트·버전·실제 파일 경로와 링크 대상도 보호합니다. 백틱 안에 있는 문자열이 설명용 한국어인지 실제 코드 토큰인지 직접 확인합니다.

사전의 설명용 한국어 표현은 기술 의미를 확인한 경우에만 바꿀 수 있습니다. 이 예외를 코드 식별자 번역에 적용하지 않습니다. 직접 인용과 원시 실행 결과는 출처의 원형을 유지합니다.

검증 상태는 별도 보호 대상으로 기록합니다. 미실행·차단·실패·일부 확인·전체 통과를 구분하고, 표현을 매끄럽게 고친다는 이유로 상태를 높이지 않습니다.

## 3. 문서 역할부터 정리

`DEV-C01`을 먼저 적용합니다. 현행 명세에 붙은 실행별 작업 기록은 적절한 이력 문서로 옮기고, 명세에는 현재 유효한 구조·계약·제한과 증거 링크를 남깁니다. 날짜·경로·프로세스 값·명령·출력은 이동 전후 그대로인지 확인합니다.

`DEV-C02`로 제품 설명과 정리된 검증 기록에 남은 작업 도구의 대화 표현을 정리합니다. 역할이 분명한 경우 검토 범위·실행 단계로 바꾸고, 불명확하면 검사 범위를 추측하지 않습니다. 실행 정책 제한으로 거부된 상태는 그대로 유지합니다.

기록을 옮겨도 기존 앵커가 끊기지 않도록 원래 절에 호환 앵커와 새 기록 링크를 남깁니다. 현재 운영에 필요한 고정 경로나 포트를 실행 기록으로 오인해 제거하지 않습니다.

## 4. 문장과 용어 교정

`DEV-A01`의 모든 용어군을 순서대로 확인합니다. 각 후보가 어떤 기능·저장 방식·조건·측정값을 뜻하는지 읽고 적합한 표현을 선택합니다. 단순 실행 여부를 정상 판정으로 바꾸거나, 파일 저장을 DB 저장으로 바꾸지 않습니다.

`DEV-A02`로 목적·이유를 직접 연결합니다. 원문에 없는 필요조건이나 의무를 추가하지 않습니다. `DEV-A03`으로 동작을 구체적인 동사로 바꾸고 주체·시제·완료 여부를 유지합니다. `DEV-A04`로 장소·수단·기준에 맞는 조사와 동사를 고릅니다.

정규식 검색 결과는 편집 후보 목록입니다. 각 문장을 읽고 수정·보존·확인 요망 가운데 하나로 판단합니다. 일치 문자열을 문맥 없이 일괄 치환하지 않습니다.

## 5. 어미와 띄어쓰기 전수 확인

`DEV-E01`은 파일마다 따로 정한 말투가 아니라 요청받은 문서 세트의 기준으로 적용합니다. 개발 안내·명세의 본문과 완결된 문장형 표 셀을 경어체로 통일합니다. 현재 설명과 과거 기록의 시제는 유지합니다.

`DEV-S01`의 네 가지 정규식 유형과 모든 예제를 확인합니다. 필요한 공백을 보완하고 단위는 근거가 있는 경우에만 추가합니다. 고유 식별자·버전·명령·원시 출력은 보존합니다.

명사구 표 셀은 그대로 둘 수 있습니다. 코드 주석·출력과 변경 금지 인용은 본문과 구분해 보고합니다. 설명용 한국어를 백틱으로 감싸 검사에서 숨기지 않습니다.

## 6. 구조와 보존 검증

대상 파일을 모두 다시 읽고 파일별 확인 여부를 기록합니다. Python 검사기로 로컬 파일 링크·헤더 앵커·정규식 후보·종결어미를 전수 검사합니다. 검사기는 코드 블록, 실제 식별자, 원본 보존용 파일과 교정 전 예문을 구분해야 합니다.

보존 검증에서는 수정 전후의 코드 블록·명령·필드·수치·날짜·해시·UUID를 대조합니다. 기록을 옮겼다면 파일별 비교만으로 누락을 판정하지 말고, 이동 전후 전체 집합과 대응 관계를 확인합니다. 실제 값이 사라지거나 바뀌면 먼저 원인을 해결합니다.

기존 `scripts/audit_revision.py`는 백틱 안의 문자열을 넓게 보호하므로 설명용 한국어를 고친 경우에도 경고할 수 있습니다. 그 경고를 숨기거나 보호 검사를 해제하지 않습니다. 어떤 설명문을 어떤 개발 규칙으로 고쳤는지 남기고, 실제 코드 토큰과 수치가 그대로인지 별도로 대조합니다. 검사 결과가 거부이면 통과로 보고하지 않습니다.

저장소에 문서 관련 pytest가 있으면 실제로 실행하고 `git diff --check`도 확인합니다. 테스트가 없거나 실행이 막혔으면 그 범위와 이유를 보고합니다. 실행하지 않은 검사 결과를 예상으로 채우지 않습니다.

## 7. 결과 보고

확인한 전체 파일 수, 수정한 파일 수, 원본 보존 때문에 제외한 파일과 이유를 구분해 보고합니다. 링크·앵커 오류, 교정 후보, 본문 어미 잔존, 문서 테스트와 공백 검사의 실제 결과를 제시합니다.

모든 검사에서 0건을 보고하려면 대상 범위의 실제 오류가 남지 않아야 합니다. 교정 전 예문·보호 토큰·보존용 사본의 제외 조건과 건수를 함께 설명합니다. 정규식이 잡지 못하는 의미·시제·문서 역할은 직접 읽어 확인한 범위를 별도로 밝힙니다.

매핑 ID를 새로 추가하면 정본 JSON, 빠른 규칙, 상세 분류, 이 절차와 [SKILL.md](../SKILL.md)의 확인 목록을 함께 갱신합니다. 모든 예제의 탐지 여부와 보호 토큰의 유지 여부를 대조한 후 완료를 보고합니다.
