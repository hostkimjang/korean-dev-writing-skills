# 설정 안내 A/B 독립 대조

사례: `v06_configuration_precedence`

지정된 원자료·계약·블라인드 본문을 대조한 문서 검토이며 실제 독자 실험 결과는 아니다.

| 문서 | 필수 의미 | 독자 질문 | Hard fail | 구체적 수정 사항 |
| --- | --- | --- | --- | --- |
| A | 13/13 preserved | 5/5 sufficient | 없음 | 없음 |
| B | 13/13 preserved | 5/5 sufficient | 없음 | 없음 |

**비교 판정: 동률.**

두 문서 모두 13개 필수 의미와 5개 질문에 충분한 근거를 제공한다. A는 파일 읽기 오류와 선택값 검증 오류를 별도 제목으로 구분하고 결과를 표로 제시한다. B는 현재 디렉터리와 기존 파일 전제를 명시하고 결과 뒤에 항목별 선택 이유를 설명한다. A의 예제 제목과 앞선 기본 파일 규칙도 실행 위치를 충분히 뒷받침한다. 오류 조건을 두 절에서 함께 확인하는 경우는 있으나 필요한 조건이 누락되거나 서로 충돌하지 않는다. 원칙을 예제에 다시 적용하거나 빈 환경 변수의 실패 조건을 구체화한 부분은 현재 판단에 필요하며, 수정할 정도의 불필요한 반복은 확인되지 않았다.

## 문서 A

### 필수 의미 판정

#### K01 — preserved

항목별로 처음 존재하는 값을 고르는 순서와 서로 다른 출처를 사용할 수 있다는 예가 있어, 출처 하나가 전체 설정을 대체하지 않는 의미가 보존됐다.

인용 1:

```text
봄바람 구성 로더(`breeze-worker`)는 각 설정 항목마다 **CLI → 환경 변수 → YAML → 기본값** 순서로 처음 존재하는 값을 선택합니다. 예를 들어 `timeout_ms`는 CLI에서, `log_level`은 YAML에서 선택할 수 있습니다.
```

#### K02 — preserved

CLI·환경 변수·YAML 키의 대응, 기본값 5000, 밀리초 정수, 양 끝값을 포함하는 10~30000 범위를 모두 제시한다.

인용 1:

```text
| `timeout_ms` | `--timeout-ms N` | `WORKER_TIMEOUT_MS` | `5000` | 10~30000 정수, 단위 ms, 양 끝값 포함 |
```

#### K03 — preserved

세 출처의 이름과 기본값 info, 소문자로 제한된 네 허용값을 모두 제시한다.

인용 1:

```text
| `log_level` | `--log-level LEVEL` | `WORKER_LOG_LEVEL` | `info` | 소문자 `debug`, `info`, `warn`, `error` |
```

#### K04 — preserved

선택 후 선택값만 검사하고, 그 값이 잘못되면 시작 오류가 나며 하위 값으로 대체하지 않는다고 명시한다.

인용 1:

```text
값을 선택한 뒤에는 **선택된 값만 검증**합니다. 선택값이 유효하지 않으면 시작 오류가 발생하며, 우선순위가 낮은 값으로 대체하지 않습니다.
```

#### K05 — preserved

유효한 상위 선택값이 있으면 잘못된 하위 값 때문에 해당 설정이 실패하지 않는다고 명시한다.

인용 1:

```text
반대로 유효한 상위 값이 선택됐다면 하위 값이 유효하지 않아도 해당 설정의 시작 오류를 일으키지 않습니다.
```

#### K06 — preserved

미설정과 빈 문자열을 구분하고, 상위 CLI가 없을 때 빈 문자열도 선택되어 검증 오류가 난다고 설명한다.

```text

```
