# 2026-11-03 비교 실행

같은 여섯 요청으로 스킬 미적용(`baseline`), 업로드된 기존 스킬(`original`), 저장소의 개선 스킬(`revised`)을 한 번씩 적용했습니다. 문서 18개는 생성 후 수정하지 않았습니다. 사례의 프로젝트와 명령은 모두 가상입니다.

결과 해석과 문서별 링크는 [비교 보고서](../../../docs/evaluation.md)에 있습니다. 실행 방법과 평가 한계는 [프로토콜](../../protocol.md)을 확인하세요.

## 기록 구성

| 경로 | 내용 |
| --- | --- |
| `inputs/` | 생성자에게 실제로 전달한 공통 요청과 원자료 |
| `outputs/baseline/` | 비교 대상 스킬을 추가하지 않은 출력 6개 |
| `outputs/original/` | 업로드된 기존 스킬을 적용한 출력 6개 |
| `outputs/revised/` | 개선 스킬을 적용한 출력 6개 |
| `review-packet.json` | 평가 기준·원자료와 무작위 라벨의 출력. 평가자에게는 이 파일만 전달 |
| `reviews/` | 두 평가자가 각각 작성한 점수와 구체적인 판단 근거 |
| `label-map.json` | 채점 완료 후 공개한 라벨·조건 대응표 |
| `summary.json` | 점수 검증 후 계산한 조건별·사례별 요약 |
| `manifest.json` | 모델·작업 조건·파일 해시·실행 제약 |

같은 세션 계열 모델을 사용했으며, 개별 API 배포 ID·temperature·샘플링 시드는 노출되지 않았습니다. 비교 대상 스킬을 쓰지 않은 조건에도 플랫폼의 공통 글쓰기 지침은 적용됩니다. Claude나 Gemini에서 직접 실행한 결과가 아니며, 클라이언트의 자동 스킬 선택이나 설치 성공을 시험한 것도 아닙니다.

기존 스킬은 사용자가 제공한 ZIP의 SHA-256으로 식별하며 원본 파일은 이 공개 저장소에 넣지 않았습니다. 미적용·개선 스킬 조건의 입력과 스킬은 저장소에서 확인할 수 있습니다. 기존 스킬 조건을 다시 생성하려면 `manifest.json`에 기록한 해시와 일치하는 원본 ZIP이 필요합니다.

## 다시 평가할 때

현재 실행의 출력이나 점수를 덮어쓰지 말고 새 실행 폴더를 만듭니다. 생성은 각 사례·조건마다 새 컨텍스트에서 수행하며 평가용 명제와 다른 조건의 결과를 전달하지 않습니다. 현재 스크립트는 모델을 호출하지 않습니다.

18개 원문을 저장한 뒤 저장소 루트에서 다음 순서로 평가 자료를 준비합니다. 날짜와 시드는 새 실행에 맞게 정합니다.

```bash
python scripts/blind_outputs.py --run YYYY-MM-DD --seed 12345
```

평가자는 새 실행의 `review-packet.json`만 읽고 `reviews/judge-a.json`과 `reviews/judge-b.json`에 결과를 저장합니다. 두 결과를 동결한 다음 대응표를 열고 집계합니다.

```bash
python scripts/summarize_scores.py --run YYYY-MM-DD
```

원자료·스킬·출력 바이트와 채점 근거를 보존하는 것이 목적입니다. 모델의 비결정성과 노출되지 않은 실행 설정 때문에 같은 입력에서 문서나 점수가 그대로 재현된다고 보장하지 않습니다.
