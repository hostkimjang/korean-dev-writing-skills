# 문서 검증 테스트

문서 검사기는 저장소의 Markdown 파일을 모두 읽습니다. 로컬 링크와 절 참조는 보존 기록에서도 확인하고, 문체 검사는 수정 가능한 본문에 적용합니다. 원시 기록, 명령, 교정 전 예시는 검사 결과에서 구분해 집계합니다.

## 실행

Python과 Node.js가 필요합니다. Markdown 구조는 저장소에 포함된 파서로 읽으며 외부 페이지를 요청하지 않습니다. 테스트에는 pytest가 필요합니다.

```bash
python -m pip install --requirement requirements-dev.txt
python -m pytest tests/test_markdown.py
python scripts/check_markdown.py --json /tmp/korean-writing-markdown-audit.json
git diff --check
```

검사 결과 JSON에는 전체 파일 목록, SHA-256, 문서 역할, 예외 구간, 오류 위치가 포함됩니다. 화면에는 오류 일부만 표시할 수 있지만 JSON에는 모든 오류가 기록됩니다.

## 확인하는 내용

- 일반 링크·참조 링크·이미지와 URL로 인코딩된 파일 경로를 확인합니다.
- 제목, 중복 제목, Setext 제목, 명시적인 HTML 앵커, 각주 참조를 확인합니다.
- 기존 제목을 바꿨다면 이전 앵커가 남아 있는지 확인합니다.
- 명령·기술 식별자·수치가 사라지거나 바뀌면 오류로 보고합니다. 이력 파일로 옮긴 값은 새 위치에 원문이 있는지 확인합니다.
- 원본 보존 구간은 기록한 SHA-256과 실제 원문 바이트를 대조합니다.
- 개발 문서 규칙의 ID와 필수 탐지 표현을 사전·지침·점검표 사이에서 대조합니다.
- 탐지 표현을 코드 표기로 감싼 경우에도 자연어 본문과 실제 식별자를 구분합니다.

정규식 결과는 의미 보존의 자동 판정이 아닙니다. 치환 후보의 기술적 뜻, 수치와 주장의 대응, 현행 명세와 과거 증거의 구분은 원자료를 읽고 검토합니다.

## 보존 범위

기준 커밋은 `371682457527462305d13b75641045b7c16ffdb1`입니다. 검사에 사용하는 작업 사본에서 이 커밋을 읽을 수 있어야 합니다. 별도 테스트 자료를 검증할 때만 기준을 생략할 수 있습니다.

과거 평가의 입력·출력·스킬 고정본, 원시 기록 디렉터리, 원문 그대로 공개한 예제는 바이트를 보존합니다. 교정 전 열은 해당 셀만 검사에서 구분하며, 교정 후 열과 설명은 계속 검사합니다. 예외 구간에는 이유가 필요하고, 닫히지 않았거나 중첩된 예외 표시는 오류로 처리합니다.

기존 보존 기록에는 인용한 원문의 절을 가리키는 상대 앵커 1개가 남아 있습니다. 검사기는 이 링크가 보존 기록 안에서는 끊겨 있다는 상태를 별도 항목으로 보고합니다. 기록과 원문의 해시, 인용문, 원래 절의 존재를 모두 확인해야 이 항목으로 분류합니다. 수정 가능한 문서의 깨진 링크와 합쳐서 전체 링크 오류가 없다고 표시하지 않습니다.
