# core 묶음 독립 검토

## 검토 범위와 판정 방식

입력은 `packet-core.json`의 원자료, `verifiable_claims`, `expected_checks`, `must_preserve`, 사용자 요청과 익명 문서 12개다. 지정 입력 외의 저장소 파일, 이전 평가, 웹 자료는 사용하지 않았다. 문서의 설치·실행·테스트 명령은 실행하지 않았으며, 원자료와의 문자열 및 의미 일치만 확인했다. 출력 문서는 수정하지 않았다.

아래의 **보존**은 필수 의미가 직접 서술되거나 충분한 범위의 요약으로 전달된 경우다. **부분보존**은 핵심 방향은 맞지만 해당 필수 사실 묶음의 일부 맥락·한정·목적이 빠진 경우다. **누락**은 해당 의미가 전달되지 않는 경우, **충돌**은 반대 사실이나 근거 없는 확정을 제시한 경우다. 부분보존의 크기와 성격은 함께 적었다. 같은 의미를 항목별로 열거하지 않았다는 이유만으로 누락으로 처리하지 않았다.

선택 명제는 필수 충족 판정에 넣지 않았다. 문체·구성의 차이는 사실 오류 및 요청 위반과 분리했다. 사람을 대상으로 이해도·기억·피로를 측정하지 않았으며, 아래의 표현 평가는 문서에 나타난 배치와 문장 관계에 한정한다. 점수 합계나 문서 순위는 만들지 않았다.

## 주요 발견

- README 세 문서, 진단 PR 세 문서, 문단 교정 세 문서는 각각의 필수 검증 명제를 모두 보존한다. 제공된 `hard_fail_if`에 해당하는 문제는 없다.
- 짧은 관측 PR 세 문서도 관측을 원인 확정이나 문제 해결로 바꾸지 않았으며, 실행하지 않은 테스트나 수집하지 못한 새 로그를 검증 근거로 내세우지 않는다. 원문 끝 개행을 제외하면 각각 395자, 396자, 397자로, 실제 요청인 “250~400자 정도”에 들어간다.
- 짧은 PR에는 작은 압축 손실이 있다. 세 문서 모두 추가 로그로 “항목이 언제 남고 사라졌는지 비교한다”는 세부 목적은 직접 밝히지 않는다. `doc-8c36f968`은 서비스명을 생략했다. `doc-8c36f968`과 `doc-d1aaaeec`은 응답 유실·중복 처리 여부가 미확인임을 유지하지만, 그 판단의 한계가 “로그 이름과 출력 순서만으로는 확인할 수 없다”는 데 있음을 직접 연결하지 않는다. 이들은 사실의 반전이나 치명적인 허위 보고와 구분해야 한다.
- 문단 교정은 세 문서 모두 제목·해설·목록·표 없이 완성된 본문만 제공한다. 문단 수, 인라인 코드 표시, README와 PR의 제목 및 표 구성은 요청과 충돌하지 않는다.

### 선택 명제, 명령, 조건 및 새 사실

- RC8의 로그 추적·날짜 범위 기능 부재, RC9의 네트워크 미전송은 선택 명제다. 세 문서 모두 원자료와 일치하게 포함한다. 선택 명제의 포함 자체를 별도 우열 근거로 삼지 않는다.
- 세 문서 모두 `trace-slice`, `0.4.2`, `INPUT`, `--level`, `--output`, `debug`, `info`, `warn`, `error`, `./logs/api.jsonl`, `level`, Python 버전과 Ubuntu 버전 식별자를 보존한다. 도움말 명령 `trace-slice --help`도 일치한다.

### 문단 연결·정보 배치·표현 비교

**doc-7a306093.** “설치” → “첫 실행: 오류 로그 확인하기” → “사용 형식과 주요 옵션” 순서로 설치 후 실행을 먼저 제시한다. “이 명령은 `error` 항목을 표준 출력으로 내보냅니다”가 명령 바로 다음에 있어 실행 예의 결과가 분리되지 않는다. 옵션 표는 값과 기본 동작을 함께 담으며 덮어쓰기 조건도 같은 행에 둔다. 마지막 “사용 중 알아둘 점”에는 입력 오류 처리와 미지원 기능이 함께 들어간다. 모두 필요한 설명이지만, 오류 처리와 버전의 기능 제약을 별도 범주로 찾으려면 같은 절 안에서 항목을 구별해야 한다. 이는 구성상의 선택이며 내용 누락은 아니다.

**doc-2867ca34.** “설치와 첫 실행”을 번호 단계로 묶어 설치·도움말·실제 입력 실행의 순서를 명시한다. “`INPUT`, `LEVEL`, `PATH`는 각각 사용할 파일 경로, 심각도, 저장 경로로 바꾸세요”는 사용 형식의 자리표시자를 설명한다. “입력 오류 처리”와 “0.4.2의 제약”이 분리되어 서로 다른 성격의 내용을 별도 제목에서 확인할 수 있다. 한편 `INPUT`의 필수 여부와 덮어쓰기는 본문과 표에서 반복된다. 이 반복은 새 의미를 더하지 않는 부분도 있지만, 오류로 볼 이유는 없으며 글의 길이만으로 평가하지 않는다.

**doc-41fb9dd4.** “기본 심각도로 확인”, “경고 이상의 로그를 파일로 저장”이라는 실제 사용 상황을 실행 예와 연결한다. 특히 덮어쓰기 경고를 파일 저장 명령 바로 앞에 둔다. 생성한 파일 경로와 결과에 포함되는 심각도도 뒤 문장에서 설명한다. “심각도는 … 순으로 높아집니다”, 출력 대상 표, 기본 심각도 실행 예가 같은 필터 규칙을 여러 방식으로 보여 준다는 특성이 있다. 주 옵션 표의 `--output` 행 자체에는 덮어쓰기 조건이 없어서 그 행만 발췌하면 해당 조건이 빠진다. 문서 전체에는 명확히 존재하므로 필수 명제 누락으로 처리하지 않는다. 입력 오류 표 뒤의 “위 안내와 오류”는 바로 앞 표를 가리키는 것으로 문맥이 성립하지만, 어떤 안내인지 표를 참조하는 표현이다.
