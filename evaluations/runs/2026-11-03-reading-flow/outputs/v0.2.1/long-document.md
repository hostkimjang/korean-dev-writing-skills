# 모래결 색인 갱신기: 요청 접수부터 검색 반영까지

모래결 색인 갱신기는 자료집의 문서를 검색할 색인을 만드는 내부 서비스다. 원본 업로드는 별도 시스템이 담당하며, 이 서비스는 보관이 끝난 원본을 선택해 색인을 갱신한다. 조회 API가 검색에 사용하는 대상은 원본이 아니라 활성 색인이다.

갱신을 요청한 뒤에는 접수 응답, 작업 상태, 검색 결과를 함께 읽어야 한다. 접수 성공은 작업 기록이 저장되었다는 뜻이고, 완료는 새 색인으로의 전환이 확정되었다는 뜻이다. 검색 결과를 해석할 때는 해당 검색이 전환 전후 어느 시점에 시작했는지도 살펴야 한다. 이 문서의 서비스명과 사례는 모두 가상이다.

## 구성 요소와 원본이 검색에 반영되는 경로

갱신은 접수 API에서 시작한다. 접수 API가 요청을 확인해 작업 기록을 남기면, 작업 조정기가 그 작업을 구축기에 넘긴다. 구축기는 선택된 원본으로 후보 색인을 만들고 검증한다. 검증을 통과한 후보를 활성 색인으로 반영하는 주체는 조정기다.

조회 API는 이 과정에서 활성 색인으로 검색한다. 구축 중인 후보는 활성 색인과 분리되어 보관되므로, 후보에 일부 문서만 만들어진 상태가 검색 결과에 섞이지 않는다. 기존 활성 색인이 있는 자료집이라면 새 후보를 만드는 동안에도 그 기존 판으로 검색한다. 처음 색인을 만드는 자료집처럼 활성 판이 아직 없는 경우의 응답은 뒤에서 따로 설명한다.

## 자료집, 원본, 요청, 색인을 구분하는 식별자

갱신 과정을 따라가려면 무엇을 가리키는 번호인지 먼저 구분해야 한다. 예를 들어 자료집 `C17`의 원본 `r18`을 갱신해 달라는 요청 `q203`이 색인 `i52`를 만들 수 있다.

| 식별자 | 사례 | 가리키는 대상 |
| --- | --- | --- |
| 자료집 번호 | `C17` | 색인을 갱신할 자료집 |
| 원본 번호 | `r18` | 내용이 고정된 원본 한 묶음 |
| 접수 번호 | `q203` | 접수한 갱신 작업. 작업 상태를 조회할 때 사용한다. |
| 색인 판 번호 | `i52` | 만들어진 색인의 판 |

`r18`, `q203`, `i52`의 숫자는 각각 별도 순서다. 숫자끼리 비교해 진행률이나 최신 여부를 판단할 수 없다. 작업 상태를 조회할 때도 접수 번호인 `q203`을 사용해야 하며, 자료집 번호나 색인 판 번호로 대신 조회할 수 없다.

원본 번호는 작업이 사용할 내용을 고정한다. `q203`이 `r18`로 접수되었다면 작업 도중 `r19`가 올라와도 끝까지 `r18`을 사용한다. 조정기와 구축기는 진행 중에 최신 원본으로 대상을 바꾸지 않는다. 따라서 갱신 완료 여부를 확인할 때는 어떤 원본을 대상으로 접수했는지도 함께 확인해야 한다.

## 접수 성공으로 알 수 있는 것

접수 API는 자료집이 존재하는지, 지정한 원본의 보관이 끝났는지 확인한다. 둘 중 하나라도 충족하지 않으면 이유를 반환하고 작업 기록을 만들지 않는다. 이 확인을 통과하더라도 같은 자료집에 진행 중인 작업이 있으면 새 작업을 받지 않는다. 한 자료집에는 진행 중 작업을 하나만 허용하기 때문이다.

요청을 받으면 작업 기록의 저장을 마친 뒤 새 접수 번호와 `대기` 상태를 반환한다. 이 응답으로 확인할 수 있는 것은 요청이 작업 목록에 들어갔다는 사실이다. 구축기가 이미 작업을 시작했는지, 검증을 통과했는지, 활성 색인이 바뀌었는지는 접수 성공만으로 알 수 없다. 접수 응답은 활성 색인 전환까지 걸리는 시간도 약속하지 않는다.

접수 번호를 받았다면 이후에는 그 번호로 작업 상태를 조회한다. 기존 활성 색인이 있는 자료집에서 접수 직후 예전 내용이 검색되더라도, 그것만으로 갱신이 실패했다고 판단할 수는 없다. 새 후보가 활성 판으로 전환되기 전까지는 기존 판을 사용하기 때문이다.

## 대기에서 완료까지 무엇을 기다리는가

정상적인 갱신은 `대기 → 구축 중 → 검증 중 → 반영 대기 → 완료` 순서로 진행한다.

| 상태 | 작업에서 일어나는 일 | 상태를 읽을 때의 기준 |
| --- | --- | --- |
| 대기 | 작업 기록은 저장되었지만 구축기가 아직 시작하지 않았다. | 접수는 끝났고 구축 시작을 기다리는 상태다. |
| 구축 중 | 선택한 원본으로 후보 색인을 만든다. | 후보는 활성 색인과 분리되어 있어 검색에 섞이지 않는다. |
| 검증 중 | 후보의 문서 수와 확인용 문서 조회를 검사한다. | 모든 검사를 통과해야 다음 상태로 간다. |
| 반영 대기 | 검증을 통과한 후보가 활성 판으로 전환되기를 기다린다. | 아직 전환 전이며, 기존 활성 판이 있다면 조회 API는 그 판을 사용한다. |
| 완료 | 활성 색인 판 변경과 작업 완료 기록이 함께 확정되었다. | 새 판으로의 전환이 확정된 상태다. |

검증에서는 후보의 문서 수가 원본과 일치하는지 확인한다. 또한 원본에 지정된 두 확인용 문서가 정확한 키로 조회되는지 검사한다. 이 검사를 모두 통과해야 `반영 대기`로 이동한다. 검증이 확인하는 범위는 문서 누락과 기본 조회이며, 검색 순위의 품질을 평가한 결과는 아니다.

`반영 대기`는 검증을 마쳤지만 검색에 사용할 판은 아직 바뀌지 않은 상태다. 조정기가 반영할 때 자료집의 활성 색인 판 변경과 해당 작업의 완료 기록을 하나의 변경으로 함께 확정한다. 따라서 검증 통과 기록이나 `반영 대기` 표시만 보고 새 내용이 이미 검색된다고 안내해서는 안 된다. 전환이 확정되었는지는 `완료` 상태로 판단한다.

작업의 종료 상태는 `완료`, `실패`, `중단`이다. `대기`, `구축 중`, `검증 중`, `반영 대기`는 모두 진행 중 상태이므로, 이 중 어느 상태에 있든 같은 자료집의 진행 중 작업 자리를 차지한다.

## 완료 상태와 실제 검색 결과를 함께 읽기

조회 API는 검색 요청을 시작할 때 활성 판을 한 번 정하고, 응답을 마칠 때까지 그 판을 유지한다. 검색 도중 활성 판이 바뀌어도 같은 요청 안에서 두 판의 결과를 섞지 않는다.

예를 들어 기존 활성 판으로 검색 요청을 시작한 뒤 `q203`의 반영이 확정되었다고 하자. 이 검색은 `q203`이 완료된 뒤 응답하더라도 기존 판의 결과를 반환할 수 있다. 반영이 확정된 뒤 시작한 검색은 새 판인 `i52`를 사용한다.

따라서 완료 상태를 확인한 시각과 검색 응답을 받은 시각만 비교해서는 부족하다. 완료 뒤 도착한 응답이 예전 내용이라면 검색이 전환 전에 시작했는지 살펴야 한다. 새 판의 결과를 확인하려면 전환이 확정된 뒤 시작한 검색의 결과를 읽어야 한다.

## 실패하거나 첫 갱신이 끝나지 않았을 때

구축 또는 검증을 더 진행할 수 없는 오류가 나면 작업은 `실패`로 끝난다. 상태 조회에는 오류가 발생한 단계와 이유가 남으며, 해당 후보는 활성 판으로 반영하지 않는다. 기존 활성 판이 있었다면 계속 사용하므로 갱신 실패가 기존 검색의 중단을 뜻하지는 않는다.

한 번도 반영을 마치지 않은 자료집에는 유지할 기존 활성 판이 없다. 첫 갱신이 진행 중이거나 `실패` 또는 `중단`으로 끝났다면 조회 API는 `색인 준비 안 됨`을 반환한다. 이는 검색을 정상적으로 수행했지만 결과가 없어 빈 목록을 반환하는 경우와 구분해야 한다.

## 중단 요청이 수락되어도 기다려야 하는 이유

중단 요청은 `대기`, `구축 중`, `검증 중`에만 받는다. `반영 대기`와 종료 상태인 `완료`, `실패`, `중단`에서는 거절한다. 수락 가능 여부는 사용자가 중단 버튼을 누른 시각이 아니라 조정기가 요청을 확인한 시점의 작업 상태로 판단한다. 버튼을 누를 때 `검증 중`이었더라도 조정기가 확인할 때 `반영 대기`라면 중단 요청은 거절된다.

중단 요청을 수락하면 먼저 중단 표시를 남긴다. 이후 조정기나 구축기가 그 표시를 확인하고 실제로 작업을 멈춘 뒤에야 상태를 `중단`으로 바꾼다. 그동안 상태 조회에는 직전의 진행 중 상태가 보일 수 있다. 중단 요청 수락과 작업의 중단 완료를 구분해야 하는 이유다.

중단 표시가 남은 후보는 검증을 마치더라도 `반영 대기`로 넘어가거나 활성화될 수 없다. 기존 활성 판이 있는 자료집은 계속 그 판으로 검색한다. 기존 활성 판이 없다면 앞서 설명한 `색인 준비 안 됨` 상태가 이어진다.

진행 중 작업 제한도 상태가 실제로 `중단`이 된 뒤에 풀린다. 중단 요청을 수락했더라도 아직 진행 중 상태라면 같은 자료집의 자리를 차지한다. 이때 새 갱신이나 재시도를 요청하면 `진행 중 작업 있음`과 진행 중인 작업의 접수 번호를 반환하며, 새 접수 번호는 만들지 않는다. 이 제한은 다른 자료집의 접수에는 영향을 주지 않는다.

## 재시도와 다른 원본으로 갱신하기

재시도는 `실패` 또는 `중단`으로 끝난 작업에만 요청할 수 있다. 재시도가 수락되면 기존 작업 기록은 그대로 두고 새 접수 번호를 발급해 `대기`부터 시작한다. 이전 후보나 문서별 진행 위치를 이어 쓰지 않고 처음부터 다시 구축하며, 사용하는 원본 번호는 기존 작업과 같다.

예를 들어 `r18`을 사용한 `q203`이 실패한 뒤 `r19`의 보관이 끝났더라도, `q203`을 재시도하면 다시 `r18`로 구축한다. `r19`를 반영하려면 진행 중 작업이 없는 때에 `r19`를 지정한 일반 갱신을 요청해야 한다. 같은 원본의 작업을 다시 수행할지, 다른 원본을 선택해 새로 갱신할지에 따라 요청을 구분한다.

기존 검색에 미치는 영향은 새 요청에서도 같다. 기존 활성 판이 있다면 재구축과 검증을 진행하는 동안 그 판을 사용하고, 새 후보의 반영이 확정되어야 활성 판이 바뀐다. 기존 활성 판이 없다면 재시도를 접수한 것만으로 검색이 준비되지는 않는다.

## 아직 확정되지 않은 운영 정책

현재 자료로 설명할 수 있는 재시도는 앞서 다룬 수동 재시도의 조건까지다. 다음 항목은 미확정이다.

- 대기 시간의 상한
- 자동 재시도 여부와 간격
- 실패하거나 중단한 후보의 보관 기간
- 반영 단계에서 발생한 오류의 복구 절차

이 항목에 대해서는 시간 보장이나 자동 복구를 전제로 판단할 수 없다. 접수 뒤의 진행 상황은 접수 번호로 확인하고, 완료된 갱신의 검색 결과는 활성 판 전환과 검색 요청 시작 시점을 함께 고려해 해석한다.
