# 긴 문서의 읽기 흐름

독자가 앞 내용을 계속 외우거나 다시 찾아야만 다음 설명을 이해하는 지점을 줄인다. 사실·조건·예외를 보존하면서 설명의 순서와 연결을 다듬는다.
긴 문서나 이해하기 어려운 설명에 필요한 항목만 적용한다. 이미 짧고 명확한 문서에 개요·목차·요약을 추가하지 않는다.

## 1. 읽는 목적과 독자를 정한다

같은 내용을 모두 같은 순서로 설명하지 않는다. 독자가 문서를 읽고 무엇을 해야 하는지에 따라 먼저 필요한 정보를 고른다.

| 주된 목적 | 우선 연결할 내용 |
| --- | --- |
| 이해하기 | 대상과 핵심 구분, 구성 요소의 관계, 동작의 이유와 경계 |
| 실행하기 | 적용 조건, 준비 상태, 단계별 행동과 확인·중단 기준 |
| 찾아보기 | 찾을 대상이 드러나는 제목, 일관된 용어, 값·조건·예외의 위치 |

- 이 문서의 개념·동작이 낯선 독자에게는 설명에 필요한 개념과 전제를 먼저 소개한다. 여러 약어와 구성 요소를 한꺼번에 정의한 뒤 오래 기억하게 하지 않는다.
- 이 문서의 개념·동작에 익숙한 독자에게는 기초 지식을 반복하기보다 현재 문서에서 달라지는 동작·조건·판단을 설명한다.
- 여러 독자를 위한 문서는 공통 핵심을 먼저 두고 필요한 세부 절로 안내한다. 맥락으로 알 수 있는 독자 수준을 매번 질문하지 않는다.

## 2. 첫 문단에서 읽을 방향을 알려 준다

대상과 문서의 목적, 독자가 먼저 알아야 할 핵심 구분을 밝힌다. 제목도 내용의 대상·동작·범위를 드러내며 본문이 제공하지 않는 답을 약속하지 않는다.

- 절이 많거나 읽는 경로가 갈리면 주요 질문이나 읽을 순서를 짧게 안내한다. 목차를 본문에서 다시 장황하게 풀어 쓰지 않는다.
- 결론이나 사용 조건을 알아야 뒤 내용을 이해할 수 있다면 앞에서 알려 준다. 흥미를 끌려고 필요한 답을 뒤로 미루지 않는다.
- 문서의 실제 쓰임이 드러나면 충분하다. 모든 도입에 질문·일화·과장된 문제 상황을 만들지 않는다.
- 제목의 글자 수, 독자의 집중시간, 소제목 수를 고정하지 않는다. 글을 특정 시간 안에 읽히게 하려고 필요한 조건을 덜어 내지 않는다.

## 3. 소제목과 문단 첫 문장으로 현재 위치를 보여 준다

- 소제목은 큰 질문이나 주제가 바뀌는 곳에 둔다. `기타`, `상세 설명`처럼 내용을 예측하기 어려운 제목은 실제 주제로 바꾼다.
- 제목 단계는 내용의 포함 관계를 나타낸다. 글자 크기를 바꾸기 위해 단계를 건너뛰거나 매 문장마다 새 제목을 만들지 않는다.
- 문단 첫 문장에서 중심 내용을 파악할 수 있게 한다. 앞 문단에서 이미 분명한 주제를 매번 다시 선언하지는 않는다.
- 한 문단에서 중심 설명과 관련 없는 배경·예외·참고 사항이 길어지면 필요한 위치로 옮긴다. 현재 판단에 필요한 예외는 함께 남긴다.
- 작은 전환은 연결 문장으로 처리한다. 소제목·굵은 글씨·요약을 동시에 겹쳐 모든 문장을 강조하지 않는다.
- 제목만 훑어도 문서의 범위와 읽는 순서가 드러나는지 확인한다. 제목을 잘 붙였다는 이유로 본문의 설명 부족을 넘기지 않는다.
- 통독 뒤에도 따로 찾을 초기 상태의 예외와 오류·거절·중단 기준은 제목이나 표의 항목명에 드러낸다. 정상 흐름 제목 아래 관련 없는 예외까지 묻지 않는다. 짧은 본문에서 바로 찾을 수 있는 내용에 별도 목차를 만들 필요는 없다.

## 4. 알려진 내용에서 새 내용으로 이어 간다

- 앞에서 소개한 대상이나 상태를 기준으로 새 동작·이유·예외를 설명한다. 설명 대상이 바뀌면 그 이름을 밝혀 독자가 전환을 알아볼 수 있게 한다.
- 원인과 결과, 대조, 조건과 동작의 관계가 빠져 있으면 자료에 근거해 연결한다. 인과관계가 확인되지 않았다면 인과처럼 잇지 않는다.
- `따라서`, `반면`, `이때`를 넣기 전에 정보의 순서가 맞는지 확인한다. 연결어만 늘려 논리의 빈틈을 덮지 않는다.
- `이것`, `해당`, `그 결과`가 여러 대상을 가리킬 수 있으면 필요한 이름을 다시 쓴다. 준비·재시도·승인처럼 독립 조회하는 절의 `두 설정`, `위 조건`도 실제 이름이나 핵심 조건으로 바꿔 앞 절을 찾지 않고 판단하게 한다.
- 같은 개념은 같은 용어로 이어 간다. 표현의 반복을 피하려고 구성 요소·상태·단계를 다른 이름으로 바꾸지 않는다.
- 짧게 나눈 문장 사이에 조건이 걸쳐 있거나 읽는 흐름이 끊기면 다시 연결한다. 긴 문장과 짧은 문장을 규칙적으로 번갈아 배치하지 않는다.
- 길이나 문장 수보다 새로운 개념의 수와 관계를 살핀다. 필요한 연결을 지워 문장을 짧게 만드는 것은 개선으로 보지 않는다.

## 5. 함께 이해해야 하는 정보를 가까이 둔다

- 개념을 설명한 뒤 필요한 예시를 가까이 두고, 예시의 어떤 부분이 설명한 개념을 보여 주는지 짚는다.
- 명령 앞에는 적용 조건과 작업 위치를, 뒤에는 확인 결과와 실패·중단 대응을 둔다. 명령 절만 찾아온 독자도 필요한 상태·권한·시간 한계를 확인하게 하며, 시간은 어느 사건부터 세는지 적는다. 접수 응답만으로 다음 명령을 실행하면 안 되는 경우 그 경계를 실행 위치에 남긴다. 모든 명령에 관련 없는 경고를 붙이지 않는다.
- 표·코드·도식에 긴 설명이 필요하면 그 설명이 참조하는 대상을 명확히 표시한다. 서로 떨어진 표 두 개를 머릿속에서 합쳐야만 핵심을 알게 하지 않는다.
- 비교는 같은 기준에서 나란히 보여 준다. 조건이 다른 측정값을 같은 기준의 우열처럼 배치하지 않는다.
- 상세 자료로 이동하기 전에 현재 단계의 판단에 필요한 정보를 제공한다. 실제로 없는 예시·성공 출력·측정값을 보충하지 않는다.
- 같은 판정의 조건·응답·예외와 알려진 재요청 가능 시점은 한 절이나 표에서 완결되게 설명한다. 다른 절에서는 기준을 찾을 위치를 가리킬 수 있지만, 그 절의 행동을 바꾸는 조건을 참조만 남기고 지우지 않는다.
- 시스템이 상태를 바꾸거나 값을 고르는 기준과, 독자가 상태를 확인하는 절차를 나누어 설명한다. 예를 들어 완료를 조회한 뒤 결과를 확인하는 순서를 권할 수 있지만, 그 조회가 시스템 완료의 필요조건이라고 바꾸지 않는다. 실제로 조회가 상태를 바꾸는지는 원자료에 따른다.

## 6. 다음 판단에 필요한 내용을 짧게 다시 연결한다

- 독자가 흐름을 잃기 쉬운 전환이나 긴 설명 뒤에서는 다음 절에 필요한 구분이나 상태를 짧게 되짚고, 다음 이해·행동·판단과의 관계를 밝힌다. 앞 절 전체를 다시 요약하거나 매 절에 개요·요약·결론을 붙이지 않는다.
- 이름·핵심 구분·판정 조건으로 충분하면 이미 설명한 원리와 배경을 다시 풀지 않는다. 반복을 줄인 뒤에도 해당 절의 판단에 필요한 내용이 남아 있는지 확인하고, 복수 조건과 예외를 문장 수에 맞춰 생략하지 않는다.
- 실행 직전의 경고·중단 조건이나 독립적으로 찾아 읽는 절의 전제는 필요하면 다시 적는다. 중복 제거를 이유로 중요한 조건을 한 곳에만 남기지 않는다.
- 중요한 상태를 다시 언급할 때도 근거의 강도를 유지한다. 조사 중인 가설이 반복되는 사이 확정 원인으로 바뀌지 않게 한다.
- 표 뒤 설명은 표에 없는 해석·관계·선택 이유가 있는지 확인한다. 같은 장점과 동작 순서를 다시 나열하는 부분은 지우거나 통합한다. 표가 이미 이유까지 설명하면 별도 해설을 채우지 않는다.

## 7. 본문과 참고 자료의 역할을 나눈다

- 본문에는 이해·실행·판단에 필요한 경로를 남긴다. 상세 옵션 목록, 전체 로그, 긴 근거 자료는 필요한 경우 별도 절이나 실제로 존재하는 문서로 연결한다.
- 핵심 제약, 적용 범위, 필수 선행조건, 실패 시 중단 기준을 접힌 영역이나 먼 부록에만 숨기지 않는다.
- 링크에는 이동해서 무엇을 확인할 수 있는지 드러낸다. 현재 설명을 이해하려면 모든 링크를 열어야 하는 구성은 피한다.
- 기술 참조 문서는 찾아보는 기능도 고려한다. 순서대로 읽기 좋게 고친다는 이유로 익숙한 항목명이나 값의 위치를 불필요하게 바꾸지 않는다.

## 8. 형식은 내용의 관계를 드러내는 데 쓴다

- 설명과 인과관계는 문단으로 이어 간다. 문장마다 줄을 바꾸거나 불릿을 붙여 서로 연결된 설명을 조각내지 않는다.
- 순서가 있는 행동은 번호로, 독립된 항목은 목록으로, 같은 기준의 비교와 대응 관계는 표로 보여 준다.
- 중단·거절 조건이 여러 개면 공통 조치를 밝히고 조건을 분리한다. `모두 충족할 때`와 `하나라도 해당하면`의 논리를 남기며, 조건마다 대응이 다를 때는 대응 표를 쓴다.
- 긴 산문을 표의 셀에 밀어 넣지 않는다. 좁은 화면에서 열이 많아 읽기 어려우면 비교 기준을 줄이거나 별도 설명으로 나눈다.
- 문단 사이의 공백으로 주제의 경계를 드러낸다. 문단 길이는 고정하지 말고 필요한 설명이 한 덩어리로 읽히는지 확인한다.
- 도식은 순서·분기·책임 관계를 문장보다 쉽게 보여 줄 때 사용한다. 장식용 그림이나 본문과의 목적 없는 중복은 줄이되, 도식을 이해하는 데 필요한 설명·대체 텍스트·필수 조건은 남긴다.
- 강조는 놓치면 판단이 달라지는 핵심이나 중요한 구분에 한정한다. 모든 문장을 굵게 하거나 같은 정보를 여러 형식으로 목적 없이 반복하지 않는다.

## 9. 설득 구조는 문서의 목적에 맞을 때만 쓴다

기술 글이나 제안문에서 주장을 설명해야 한다면 **주장 → 이유 → 사례 → 제안 또는 핵심 재확인**의 흐름을 선택할 수 있다. OREO는 이 흐름을 기억하는 작성 틀로만 사용한다.

- 근거와 사례는 확인된 자료에서 가져온다. 설명을 위한 가상 예시는 실제 성과·경험과 구분한다.
- 마지막 부분은 필요한 판단이나 다음 행동을 밝혀 준다. 앞의 주장을 그대로 반복할 의무는 없다.
- API 계약, 찾아보는 문서, 운영 절차 전체를 이 틀로 바꾸지 않는다. 주장·이유보다 필요한 값이나 실행 조건을 먼저 찾아야 할 수 있다.

## 10. 가상 예시: 흩어진 사용 조건을 연결하기

다음은 배치와 연결만 바꾸는 가상 예시다. 요청·상태의 식별자와 판단 조건은 동일하다.

**교정 전**

> 업로드를 요청하면 `upload_id`를 받습니다. 상태 조회에는 이 값을 사용합니다. `pending`은 완료가 아닙니다. 파일은 `ready`에서만 내려받습니다. 상태는 `GET /uploads/{upload_id}`로 조회합니다.

**교정 후**

> 업로드를 요청하면 `upload_id`를 받습니다. 이 값으로 `GET /uploads/{upload_id}`를 호출해 업로드 상태를 확인합니다. `pending`은 아직 완료되지 않은 상태이며, 파일은 `ready`에서만 내려받습니다.

ID와 사용처, 상태와 가능한 행동을 각각 묶었다. 완료 시간, 자동 재시도, 새 상태값은 추가하지 않는다.

## 11. 독자의 입장에서 다시 읽는다

1. 첫 문단과 소제목에서 대상·목적·핵심 구분을 파악할 수 있는가?
2. 새 개념이나 동작이 나올 때 앞 절과의 관계를 알 수 있는가? 필요한 전제나 이유가 생략되지 않았는가?
3. 먼 절을 다시 열거나 여러 지시 대상을 추측해야만 이해되는 구절이 있는가?
4. 초기 상태·명령·오류 응답을 소제목에서 바로 찾아 읽어도 필요한 이름, 복합 조건, 시간의 시작 기준, 중단·재요청 조건이 연결되는가?
5. 반복을 줄이면서 경고·예외를 잃거나, 요약을 보태면서 같은 설명을 늘리지 않았는가?
6. 더 읽기 쉬워 보인다는 이유로 사실·조건·확실성·검증 상태나 판단 한계의 이유가 달라진 부분을 놓치지 않았는가? 시스템의 동작 조건을 사람의 확인 행동으로 바꾸지 않았는가?

이 점검을 실제 독자의 이해도·피로 측정으로 보고하지 않는다. 사용자에게 실제로 시험하지 않았다면 읽는 시간이 줄거나 더 잘 기억한다고 단정하지 않는다.

작성·교정 범위에서 발견한 문제는 본문에 반영한다. 순서와 지시 대상을 고친 뒤 해당 절부터 다시 읽고, 조건을 옮기거나 반복을 줄인 부분은 원자료와 재대조한다. 원문 보존이 필요하면 별도 교정본에 수정한다. 확인하지 못한 연구 효과를 남기는 일과 해결 가능한 편집 문제를 방치하는 일을 구분한다.

## 출처와 적용 범위

아래 연구와 공식 작성 지침을 개발 문서에 맞게 적용했다. 연구의 독자·언어·과제가 다르므로 한국어 개발 문서의 이해·기억·피로 개선을 보장하지 않는다. 원문의 예시나 수치 규칙을 그대로 옮기지 않는다.

- [Lorch·Lemarié·Chen(2013), 소제목과 예고문의 구조 신호 연구](https://journals.copmadrid.org/psed/art/ed2013a11): 출판사 전문 확인. 구조 회상과 세부 사실 기억에서 효과가 달랐다.
- [Chandler·Sweller(1992), 분산된 정보의 통합 연구](https://doi.org/10.1111/j.2044-8279.1992.tb01017.x): 출판사 초록과 동일 논문의 공개 전문 확인. 서로 참조하는 정보의 근접 배치를 참고했다.
- [McNamara 외(1996), 응집성과 사전 지식 연구](https://asu.elsevierpure.com/en/publications/are-good-texts-always-better-interactions-of-text-coherence-backg/): 저자 소속기관의 초록 확인, 전문 미확인. 독자 지식과 이해 과제에 따른 차이를 참고했다.
- [Lorch·Lorch(1995), 개요·소제목·요약 연구](https://scholars.uky.edu/en/publications/effects-of-organizational-signals-on-text-processing-strategies/): 저자 소속기관의 초록 확인, 전문 미확인. 구조를 되찾는 단서와 목적 있는 재정리를 참고했다.
- [Google Technical Writing: Paragraphs](https://developers.google.com/tech-writing/one/paragraphs): 공식 작성 지침. 문단의 중심과 연결을 참고하되 영문 문장 수 권고를 한국어 고정 기준으로 삼지 않았다.
- [W3C COGA: Use a Clear and Understandable Page Structure](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o2p03-page-structure/): 구조를 분명하게 드러내는 보조 설계 지침이며 WCAG 필수 준수 항목과 구분한다.
